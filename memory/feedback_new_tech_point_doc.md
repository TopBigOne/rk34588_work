用户 2026-10-17 明确要求："以后，只要是新的技术点，你都整理一个 md 的技术文档；因为我要学习的还有很多。"

起因：聊天里讲了 `media-ctl`、`v4l2-ctl` 是什么，用户去板子 bin 目录看到了，要求整理成用法文档。

**Why:** 用户在系统学 RK3588 音视频，聊天记录会丢、不好翻，单独的 md 文档才能反复看、能提交进仓库。

**How to apply:**
- 聊天里第一次讲到的新命令、新概念、新接口（例如 v4l2-ctl、media-ctl、devtmpfs、plane、dma_buf），讲完就主动整理成文档，不用等用户再要求；回复里说明写在哪。
- 放在当天工程的 `doc/` 下（如 `day3_cam2h264/doc/xxx.md`），并在该工程 readme 的文档导航里加一行。
- 文档风格照 [[feedback-docs-style]]：先说人话、打比方、板子实测（标日期）、最后才是代码；命令要在板子上实际跑过再写，没跑过的标"未实测"。
- 一个技术点一篇，不要塞进已有的大文档里；大文档里可以链接过去。
