## 检查重点

1. **M1～M3 的结果被 M5 改坏**：加了 pts、停顿、新方法以后，`m1`、`m2`、`m3` 的数字应该和第 01 周完全一样（1803/1803/60/60；1803 张大图；ffprobe 1803 帧）。第 8 步重跑一次。
2. **M5 某一路比另外几路先结束**：ch1（15 fps，约 902 帧）和 ch2（60 fps，约 3606 帧）时长相同，但帧数四舍五入可能差一两帧，最后几拍会出现“已结束”的格子。这些格子应该停在最后一帧，不计“重复”，程序也不能卡住。第 7 步的验收会看结束时的打印。
3. **主时钟起点**：第一张大图要等 4 路都拿到第一帧之后再拼，然后才 `start()` 时钟。不然解码器初始化的时间会被算成“晚”，开头就丢帧。第 7 步检查 ch0 的丢帧数应该接近 0。
4. **M4 的 FIFO 没有读的一方**：gst 没起来时，程序 `open` FIFO 写端会一直阻塞。脚本要先起 gst 再起程序，并且 gst 失败时程序要能被 Ctrl+C 停掉。第 4 步验证。
5. **ch3 停顿期间队列满**：解码线程睡着时队列会被取空，醒来后一下子灌进 4 帧。每一拍最多丢 3 帧，所以追上要好几拍，丢帧数会接近 60，但不一定刚好 60。m5 文档要把这一点讲清楚，第 7 步记录实测数字。

  - `void DecodeStage::setPtsFrameRate(int framesPerSecond);`：> 0 时，每交出一个正常帧前 `mpp_frame_set_pts(frame, 第几帧 × 1000000 / framesPerSecond)`（第几帧从 0 开始，用 int64_t 算）；默认 0 = 不改 pts（M1～M4 不受影响）
  - `void DecodeChannel::setDecodeStall(int stallAtFrameIndex, int stallDurationMs);`：`runDecodeLoop` 在 push 第 `stallAtFrameIndex` 帧之前睡 `stallDurationMs`；默认 -1 = 不停
  - `ComposeResult MosaicComposeStage::composeAlignedMosaic(std::vector<std::unique_ptr<DecodeChannel>> &channelPtrs, int64_t nowUs);`、`int getRepeatedFrameCount(int channelIndex) const;`、`int getDroppedFrameCount(int channelIndex) const;`。“显示”沿用 `getDrawnFrameCount`

每一格的规则（设计 5.3，照写）：

```
latest = 空
循环: r = queue.tryPopIfDue(nowUs, framePtr)
  r == Frame:      如果 latest 不空 → dropped++；latest = framePtr
  r == NotDue/Empty: 结束循环
  r == EndOfStream: 标记这一路结束，结束循环
  r == Aborted:    返回 Aborted
latest 不空 → RGA 贴进格子，drawn++
latest 空且这一路没结束 → repeated++
所有路都结束 → 返回 AllChannelsEnded（这一拍不算一张大图）
```

`runAlignedMosaicPipeline` 的流程：按 `kM5ChannelInputs` 开 4 路（`setPtsFrameRate`、`setDecodeStall`）→ 起 4 个解码线程 → 用 `composeNextMosaic` 拼第 1 张（阻塞，等 4 路第一帧都到）→ 编码 → `clock.start()` → 对 k = 1, 2, …：`clock.sleepUntilPositionUs(k × 1000000 / kM5MosaicFps)`，`composeAlignedMosaic(channels, clock.getPositionUs())`，编码 → 结束后排空编码器、join、打印每路 显示 / 重复 / 丢弃、大图张数、总用时。
