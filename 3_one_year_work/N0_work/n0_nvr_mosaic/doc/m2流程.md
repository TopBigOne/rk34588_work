## 1. 干了什么

4 路同时解码，每一路解出来的帧放进自己的队列；主线程每一轮从 4 个队列各取一帧，用 RGA 缩放成 960×540，贴进一张 1920×1080 大图里自己的格子。一共拼 1803 张大图，抽第 30 张和第 300 张存成 NV12 原始数据，拿到 Mac 上转成图片看。

```
解码线程 0：aaa.264         → 解码 → 队列 0 ┐
解码线程 1：out_720p.h265   → 解码 → 队列 1 ┤   主线程：每轮各 pop 一帧
解码线程 2：main_1080p.h264 → 解码 → 队列 2 ┤ → RGA 缩放贴进格子 → 大图
解码线程 3：out.h265        → 解码 → 队列 3 ┘   第 30、300 张 → mosaic_m2_snapshots.yuv
```

大图里格子的位置：

```
(0,0)              (960,0)
  ┌─────────────────┬─────────────────┐
  │ ch0 aaa.264     │ ch1 out_720p    │  每格 960×540
  ├─────────────────┼─────────────────┤ (0,540) / (960,540)
  │ ch2 main_1080p  │ ch3 out.h265    │
  └─────────────────┴─────────────────┘ 1920×1080
```

| 步骤 | 在哪 | 做什么 |
|---|---|---|
| 1 | `m2_compose_mosaic.cpp:70` | 建 4 个 `DecodeChannel`（解码段 + 容量 4 的队列），打开文件、创建解码器 |
| 2 | `m2_compose_mosaic.cpp:76` | 申请大图 buffer，整张涂黑；打开抓图文件 |
| 3 | `m2_compose_mosaic.cpp:86` | 每路起一个线程，跑 `DecodeChannel::runDecodeLoop`：解一帧、push 一帧 |
| 4 | `mosaic_compose_stage.cpp:68` | 主线程：每一路 pop 一帧；这一路解完了就记下来，以后跳过它 |
| 5 | `mosaic_compose_stage.cpp:80` | 从帧里读出 buffer、宽高、**这一帧自己的 stride** |
| 6 | `mosaic_compose_stage.cpp:86` | RGA `improcess`：整帧缩放到大图里这一路的格子 |
| 7 | `mosaic_compose_stage.cpp:92` | 帧释放，buffer 回到那一路解码器的内存池 |
| 8 | `m2_compose_mosaic.cpp:53` | 第 30、300 张大图写进文件 |
| 9 | `m2_compose_mosaic.cpp:97` | 4 路都解完以后，join 4 个解码线程，打印结果 |

## 4. 技术点

### 4.1 RGA

| 调用 | 在哪 | 在这里做什么 |
|---|---|---|
| `importbuffer_fd(dmaBufFd, sizeBytes)` | `rga_compositor.cpp:20` | 把解码帧的 buffer 和大图的 buffer 交给 RGA（通过 dma-buf fd），不复制数据 |
| `wrapbuffer_handle(handle, 宽, 高, 格式, horStride, verStride)` | `rga_compositor.cpp:32` | 描述图像。**源用这一帧自己的 stride**：ch3 是 2304×1080，ch0 是 1920×1088 |
| `imcheck(src, dst, srcRect, dstRect)` | `rga_compositor.cpp:82` | 先检查格式、对齐、缩放倍数，不支持就报错，不去动硬件 |
| `improcess(src, dst, {}, srcRect, dstRect, {}, IM_SYNC)` | `rga_compositor.cpp:90` | **本篇的核心**：源矩形是整帧，目标矩形是大图里的一个格子，两个大小不一样，RGA 就缩放；格子外面的像素不动 |
| `releasebuffer_handle` | `rga_compositor.cpp:98` | 让 RGA 忘掉这两块内存。内存本身还归原来的主人（解码器、拼图段） |

**`improcess` 和 Day 5 用的 `imresize` 有什么区别**：`imresize(src, dst)` 是把整张源图缩放成整张目标图，目标图有多大就缩成多大。拼图时目标是大图里的一个格子，要说清"贴到哪"，所以用 `improcess`，它多了 `srect`、`drect` 两个矩形参数（RGA 开发指南 `improcess` 一节，`Rockchip_Developer_Guide_RGA_CN.md:2115`）。第三张图 `pat` 是做混合用的，这里传空的 `{}`。

**格子的位置为什么要是偶数**：NV12 里 2×2 个像素共用一组 UV，矩形从奇数位置开始，就会把一组 UV 切成两半。RGA 开发指南的对齐表（`Rockchip_Developer_Guide_RGA_CN.md:532`，RGA3 的 NV12）要求：width stride 16 对齐；x、y、宽、高、height stride 都 2 对齐。`getCellRect` 里的 `& ~1` 就是把最低位清零，变成偶数（`mosaic_compose_stage.cpp:109`）。1920 / 2 = 960、1080 / 2 = 540，本来就是偶数，这里是防止以后改成 3×3 时出现奇数。

**为什么大图不用 RGA 涂黑**：本来想用 RGA 的 `imfill` 把大图整张涂黑，2026-11-17 在板子上实测失败，内核日志是 `rga_policy: invalid function policy`。RGA FAQ 说：RK3588 上 color fill 只有 RGA2 核能做，而 RGA2 只能访问 4GB 以内的内存（`Rockchip_FAQ_RGA_CN.md:1442`）。板子有 16GB 内存，MPP 申请的 buffer 不一定在 4GB 以内。所以改成 CPU 涂黑（见 4.2 节最后一行），只在开头做一次。缩放贴图走的是 RGA3 核，没有这个限制。

### 4.2 MPP

| 调用 | 在哪 | 在这里做什么 |
|---|---|---|
| `mpp_frame_get_buffer` / `get_hor_stride` / `get_ver_stride` | `nv12_picture.cpp:65` | 把解码帧描述成 `Nv12Picture`：画面在哪块 buffer、宽高、stride。**每一帧都读**，不能假设 4 路的 stride 一样 |
| `mpp_frame_get_fmt(frame) & MPP_FRAME_FMT_MASK` | `nv12_picture.cpp:58` | 确认是 NV12（`MPP_FMT_YUV420SP`）再交给 RGA |
| `MppFramePtr` 析构 → `mpp_frame_deinit` | `mosaic_compose_stage.cpp:92` | 贴完一帧就释放，buffer 回到**那一路**解码器的内存池。`improcess` 是同步的，返回时 RGA 已经读完 |
| `mpp_buffer_group_get_internal` + `mpp_buffer_get` | `mosaic_compose_stage.cpp:36` | 从 MPP 申请大图的 buffer（DRM 类型，有 dma-buf fd，RGA 能写，M3 的编码器能读） |
| `mpp_buffer_get_ptr` + `sync_begin` / `sync_end` | `nv12_picture.cpp:90`、`nv12_file_writer.cpp:35` | CPU 访问大图：开头涂黑（Y 写 16、UV 写 128），抓图时读出来写文件 |

**为什么黑色是 Y = 16、UV = 128**：8 bit 视频的亮度一般只用 16～235 这一段（叫"有限范围"），16 就是黑；UV 表示颜色偏离灰色多少，128 是不偏，也就是没有颜色。

### 4.3 线程：4 个生产者，1 个消费者

| 知识点 | 在哪 | 在这里做什么 |
|---|---|---|
| 每一路一个队列 | `decode_channel.h:73` | 不用 4 路共用一个队列：主线程每一轮要的是"每一路各一帧"，共用一个队列就分不清哪帧是哪一路的，也没法保证每一路各取一帧 |
| `pop` 会等 | `mosaic_compose_stage.cpp:70` | 哪一路的帧还没解出来，主线程就在它的 `pop` 里等。所以大图的速度跟着最慢的那一路走 |
| `push` 会等（背压） | `decode_channel.cpp:51` | 某一路解得快，它的队列排满 4 帧，它的解码线程就停在 `push` 里等主线程。日志里 4 路都"最多排过 4 帧"，说明 4 路解码都比拼图快，都被挡住过 |
| 一路解完：`closeInput` → `EndOfStream` | `decode_channel.cpp:40`、`mosaic_compose_stage.cpp:74` | 这一路的队列取完以后返回 `EndOfStream`，主线程记下 `isChannelEnded`，以后不再 pop 它，它的格子就停在最后一帧 |
| 4 路都解完：`AllChannelsEnded` | `mosaic_compose_stage.cpp:96` | 一整轮下来没有贴任何一帧，说明 4 路都结束了 |
| 出错时叫停所有通道 | `channel_helpers.cpp:31` | 某一路解码出错 → 它 abort 自己的队列 → 主线程 pop 到 `Aborted` → 主线程 abort 4 个队列 → 等在 `push` 里的其他解码线程被叫醒，`push` 返回 false，各自退出。这样 join 不会卡住 |

`FrameQueue` 和 Day 5 M2 的一样（mutex + `notFull`、`notEmpty` 两个条件变量），一行没改。Day 5 是 1 个生产者 1 个消费者；Day 6 是 4 个这样的队列，每个队列还是 1 个生产者（这一路的解码线程）、1 个消费者（主线程）。

### 4.4 对象的声明顺序

成员变量按声明的**反顺序**析构，这一点在两个地方很重要：

- `DecodeChannel` 里 `decodeStage` 声明在 `frameQueue` 前面（`decode_channel.h:72`）。析构时先析构 `frameQueue`：出错叫停时队列里可能还剩几帧，这些帧先释放，buffer 还回解码器的内存池；然后才析构 `decodeStage`，`mpp_destroy` 解码器、释放内存池。反过来的话，内存池先没了，剩下的帧再去还 buffer，就是还给一个已经不存在的池子。
- `MosaicComposeStage` 里 `mosaicGroupPtr` 声明在 `mosaicBufferPtr` 前面（`mosaic_compose_stage.h:76`）：先还 buffer，再释放组。

### 4.5 本篇重点

1. RGA `improcess` 的两个矩形：源矩形是整帧，目标矩形是格子，大小不同就缩放，格子外面不动
2. 4 路的 stride 各不一样，每一帧都从 MppFrame 读 stride 交给 RGA
3. 每一路一个队列；主线程每轮各取一帧；某一路解完就跳过它，格子停在最后一帧
4. 贴完马上释放帧，buffer 回到那一路解码器的内存池

### 7.2 `src/common/nv12_picture.h`

```cpp
/*
 * Nv12Picture：描述一帧 NV12 画面（在哪块 MppBuffer、宽高、stride）
 * PictureRect：画面里的一个矩形（大图里的一个格子）
 */
#pragma once

#include <rockchip/rk_mpi.h>

#include "common/mpp_utils.h"

/**
 * @brief 一帧 NV12 画面：画面在哪块 MppBuffer 里，以及 RGA、编码器、写文件时需要的宽高和 stride
 * @note 只是"描述"，不负责释放 mppBuf。谁申请的谁释放（allocNv12Buffer 返回的 MppBufferPtr，或者解码器的内存池）
 */
struct Nv12Picture {
    MppBuffer mppBuf = nullptr; // 画面所在的 MppBuffer
    int width = 0;              // 画面宽，单位像素
    int height = 0;             // 画面高，单位像素
    int horStride = 0;          // 一行在内存里占多少字节（≥ width）
    int verStride = 0;          // Y 平面在内存里占多少行（≥ height）；UV 平面从第 verStride 行开始
};

/**
 * @brief 画面里的一个矩形，单位像素，左上角是 (0, 0)
 * @note 给 RGA 用时，NV12 的 x、y、width、height 都必须是偶数（UV 是 2×2 个像素共用一组）
 */
struct PictureRect {
    int x = 0;      // 左上角横坐标
    int y = 0;      // 左上角纵坐标
    int width = 0;  // 宽
    int height = 0; // 高
};

/**
 * @brief 按"宽高都对齐到 16"的规则，描述一帧自己申请的 NV12 画面（还没有 buffer）
 * @param[in] width   画面宽，单位像素，例如 1920
 * @param[in] height  画面高，单位像素，例如 1080
 * @return mppBuf 为空的 Nv12Picture；stride = ALIGN(width, 16) × ALIGN(height, 16)，1080p 是 1920 × 1088
 * @note 解码器给的帧不用这个函数，它的 stride 由解码器决定，用 describeDecodedFrame 取
 */
Nv12Picture makeAlignedNv12Picture(int width, int height);

/**
 * @brief 从 MPP 的 buffer 组申请一块能放下 picture 的 buffer，并把它填进 picture.mppBuf
 * @param[in]     bufferGroup  从哪个组申请（DRM 类型，RGA、编码器都能用它的 dma-buf fd）
 * @param[in,out] picture      [in] 宽高和 stride；[out] mppBuf 指向新申请的 buffer
 * @return 管理这块 buffer 的 MppBufferPtr，离开作用域时自动 mpp_buffer_put；申请失败返回空（已打印原因）
 * @note 大小 = horStride × verStride × 3 / 2。返回值要接住，丢掉的话 buffer 马上就被释放
 */
MppBufferPtr allocNv12Buffer(MppBufferGroup bufferGroup, Nv12Picture &picture);

/**
 * @brief 把解码器输出的一帧描述成 Nv12Picture：取出 buffer、宽高、stride，不复制像素
 * @param[in]  decodedFrame  decode_get_frame 得到的帧，必须带 buffer（不能是只带 EOS 的空帧）
 * @param[out] picture       描述结果；mppBuf 指向解码器内存池里的 buffer，归解码器管，不要释放
 * @return true = 成功；false = 不是 NV12，或者没有 buffer（已打印原因）
 * @note picture 只在 decodedFrame 还活着的时候有效：帧释放后 buffer 回到解码器内存池，会被后面的帧覆盖
 */
bool describeDecodedFrame(MppFrame decodedFrame, Nv12Picture &picture);

/**
 * @brief 用 CPU 把整张画面涂黑：Y 平面全写 16，UV 平面全写 128
 * @param[in] picture  要涂黑的画面，buffer 必须已经申请好
 * @return true = 成功；false = 拿不到 CPU 地址（已打印原因）
 * @note 连 stride 填充的部分一起写，整块 buffer 都是确定的值。
 *       没用 RGA 的 imfill：RK3588 上填色只有 RGA2 核能做，而 RGA2 只能访问 4GB 以内的内存，
 *       板子有 16GB，MPP 申请的 buffer 不一定在 4GB 以内（2026-11-17 实测 imfill 失败，见 RGA FAQ Q4.5）
 */
bool fillNv12PictureBlack(const Nv12Picture &picture);
```

```cpp
/**
 * @brief 从 buffer 组申请一块 NV12 buffer
 * @param[in]     bufferGroup  从哪个组申请
 * @param[in,out] picture      [in] 宽高和 stride；[out] mppBuf
 * @return 管理这块 buffer 的 MppBufferPtr；失败返回空
 * @note 失败时把 picture.mppBuf 清成 nullptr，调用方不会拿到一个"半成品"
 */
MppBufferPtr allocNv12Buffer(MppBufferGroup bufferGroup, Nv12Picture &picture) {
    // NV12 一帧的大小：Y 平面 horStride × verStride 字节，UV 平面是它的一半
    const size_t frameSizeBytes = static_cast<size_t>(picture.horStride) * picture.verStride * 3 / 2;
    picture.mppBuf = nullptr;
    // mpp_buffer_get 是宏，展开成 mpp_buffer_get_with_tag(组, &buffer, 大小, 模块名, 函数名)
    if (mpp_buffer_get(bufferGroup, &picture.mppBuf, frameSizeBytes) != MPP_OK) {
        LOGE(kTag, "mpp_buffer_get %zu 字节失败", frameSizeBytes);
        picture.mppBuf = nullptr;
        return nullptr;
    }
    // 交给 MppBufferPtr 管：它离开作用域时调用 mpp_buffer_put（见 mpp_utils.h 的 MppBufferDeleter）
    return MppBufferPtr(picture.mppBuf);
}

/**
 * @brief 把解码帧描述成 Nv12Picture
 * @param[in]  decodedFrame  解码器输出的帧
 * @param[out] picture       描述结果
 * @return true = 成功；false = 格式不对或没有 buffer
 * @note 第 1 步 查格式；第 2 步 取 buffer；第 3 步 取宽高和 stride
 */
bool describeDecodedFrame(MppFrame decodedFrame, Nv12Picture &picture) {
    // 第 1 步 查格式。fmt 的高位可能带别的标志（比如 FBC 压缩），先 & MPP_FRAME_FMT_MASK 只留低位的"像素格式"
    const MppFrameFormat frameFormat = mpp_frame_get_fmt(decodedFrame);
    const int pixelFormat = frameFormat & MPP_FRAME_FMT_MASK;
    if (pixelFormat != MPP_FMT_YUV420SP) {
        LOGE(kTag, "解码帧不是 NV12：fmt = 0x%x", static_cast<unsigned>(frameFormat));
        return false;
    }

    // 第 2 步 取 buffer：解码器内存池里的一块，像素就在里面
    MppBuffer frameBuffer = mpp_frame_get_buffer(decodedFrame);
    if (!frameBuffer) {
        LOGE(kTag, "解码帧没有 buffer（只带 EOS 的空帧不该走到这里）");
        return false;
    }

    // 第 3 步 取宽高和 stride。stride 由解码器决定：1080p 的 H.264 是 1920 × 1088
    picture.mppBuf = frameBuffer;
    picture.width = static_cast<int>(mpp_frame_get_width(decodedFrame));
    picture.height = static_cast<int>(mpp_frame_get_height(decodedFrame));
    picture.horStride = static_cast<int>(mpp_frame_get_hor_stride(decodedFrame));
    picture.verStride = static_cast<int>(mpp_frame_get_ver_stride(decodedFrame));
    return true;
}

/**
 * @brief 用 CPU 把整张画面涂黑
 * @param[in] picture  要涂黑的画面
 * @return true = 成功；false = 失败
 * @note 第 1 步 拿到 CPU 地址；第 2 步 写 Y 平面；第 3 步 写 UV 平面。
 *       视频里的黑色不是 Y = 0：8 bit 视频的亮度只用 16～235 这一段（"有限范围"），16 就是黑；
 *       UV 表示颜色偏离灰色多少，128 = 不偏，也就是没有颜色
 */
bool fillNv12PictureBlack(const Nv12Picture &picture) {
    // 第 1 步 mpp_buffer_get_ptr：MPP 内部用 mmap 把这块 buffer 映射到我们的进程，返回 CPU 能用的地址
    uint8_t *frameStart = static_cast<uint8_t *>(mpp_buffer_get_ptr(picture.mppBuf));
    if (!frameStart) {
        LOGE(kTag, "mpp_buffer_get_ptr 失败");
        return false;
    }
    // CPU 写之前 sync_begin、写完 sync_end：buffer 带 cache 的话，sync_end 把 CPU cache 里的新内容写回内存，
    // 之后 RGA、编码器从内存里读到的才是黑色
    mpp_buffer_sync_begin(picture.mppBuf);

    // 第 2 步 Y 平面：horStride × verStride 字节
    const size_t yPlaneSizeBytes = static_cast<size_t>(picture.horStride) * picture.verStride;
    memset(frameStart, 16, yPlaneSizeBytes);

    // 第 3 步 UV 平面：紧跟在 Y 平面后面，大小是 Y 平面的一半
    memset(frameStart + yPlaneSizeBytes, 128, yPlaneSizeBytes / 2);

    mpp_buffer_sync_end(picture.mppBuf);
    return true;
}
```

```cpp
#include "rga/rga_compositor.h"

#include <cstring> // imcheck 是宏，展开后用到 memset，RGA 的头文件自己没 include
#include <rga/im2d.h>
#include <rga/rga.h>

#include "common/log.h"

static const char *const kTag = "RgaCompositor";

/**
 * @brief 把一块 MppBuffer 导入 RGA，得到 RGA 认识的 handle
 * @param[in] mppBuf  要导入的 MppBuffer（DRM 类型，有 dma-buf fd）
 * @return RGA handle；0 = 导入失败
 * @note 只是让 RGA 认识这块内存（通过 dma-buf fd），不复制数据。用完要 releasebuffer_handle
 */
static rga_buffer_handle_t importMppBufferToRga(MppBuffer mppBuf) {
    const int dmaBufFd = mpp_buffer_get_fd(mppBuf);                         // 这块内存的 dma-buf fd
    const int bufferSizeBytes = static_cast<int>(mpp_buffer_get_size(mppBuf)); // 这块内存一共多少字节
    return importbuffer_fd(dmaBufFd, bufferSizeBytes);
}

/**
 * @brief 把 Nv12Picture 包成 RGA 的图像描述
 * @param[in] handle   importMppBufferToRga 得到的 handle
 * @param[in] picture  画面的宽高和 stride
 * @return RGA 的图像描述（rga_buffer_t）
 * @note wrapbuffer_handle(handle, 宽, 高, 格式, 一行多少像素, 一共多少行)：最后两个就是 horStride、verStride。
 *       RGA 靠 verStride 算出 UV 平面从哪里开始，填错了颜色就错位
 */
static rga_buffer_t wrapNv12Picture(rga_buffer_handle_t handle, const Nv12Picture &picture) {
    return wrapbuffer_handle(handle, picture.width, picture.height, RK_FORMAT_YCbCr_420_SP, picture.horStride,
                             picture.verStride);
}

/**
 * @brief 把 PictureRect 换成 RGA 的 im_rect
 * @param[in] rect  我们自己的矩形
 * @return RGA 的矩形，字段一一对应
 * @note 不让 pipeline 层直接用 RGA 的类型，换 RGA 版本或者换成别的硬件时只改这个文件
 */
static im_rect toImRect(const PictureRect &rect) {
    im_rect imRect;
    imRect.x = rect.x;
    imRect.y = rect.y;
    imRect.width = rect.width;
    imRect.height = rect.height;
    return imRect;
}

/**
 * @brief 缩放后贴进格子
 * @param[in] srcPicture  源画面
 * @param[in] dstPicture  目标大图
 * @param[in] dstRect     目标格子
 * @return true = 成功；false = 失败
 * @note 第 1 步 导入两块 buffer；第 2 步 包成 RGA 图像；第 3 步 检查参数；第 4 步 缩放贴图；第 5 步 释放 handle
 */
bool resizeNv12IntoRectByRga(const Nv12Picture &srcPicture, const Nv12Picture &dstPicture, const PictureRect &dstRect) {
    // 第 1 步 导入两块 buffer
    const rga_buffer_handle_t srcHandle = importMppBufferToRga(srcPicture.mppBuf);
    const rga_buffer_handle_t dstHandle = importMppBufferToRga(dstPicture.mppBuf);
    if (srcHandle == 0 || dstHandle == 0) {
        LOGE(kTag, "importbuffer_fd 失败：src handle %u，dst handle %u", srcHandle, dstHandle);
        if (srcHandle != 0) {
            releasebuffer_handle(srcHandle);
        }
        if (dstHandle != 0) {
            releasebuffer_handle(dstHandle);
        }
        return false;
    }

    // 第 2 步 包成 RGA 图像。源画面用它自己的 stride：H.264 1080p 是 1920×1088，H.265 1080p 是 2304×1080
    const rga_buffer_t srcImage = wrapNv12Picture(srcHandle, srcPicture);
    const rga_buffer_t dstImage = wrapNv12Picture(dstHandle, dstPicture);
    const im_rect srcImRect = toImRect({0, 0, srcPicture.width, srcPicture.height}); // 源：整张画面
    const im_rect dstImRect = toImRect(dstRect);                                    // 目标：大图里的一个格子

    // 第 3 步 检查参数：格式、对齐、缩放倍数这台 RGA 支不支持。不支持时 imcheck 返回错误，不会去动硬件
    bool isComposeOk = false;
    const IM_STATUS checkStatus = imcheck(srcImage, dstImage, srcImRect, dstImRect);
    if (checkStatus != IM_STATUS_NOERROR) {
        LOGE(kTag, "imcheck：%s", imStrError(checkStatus));
    } else {
        // 第 4 步 缩放贴图。improcess(源, 目标, 第三张图, 源矩形, 目标矩形, 第三张图的矩形, usage)：
        //   第三张图（pat）用来做混合，这里不用，传空的 {}；
        //   源矩形和目标矩形大小不一样时，RGA 自动缩放；目标矩形以外的像素不动；
        //   IM_SYNC：等 RGA 做完才返回
        const IM_STATUS processStatus = improcess(srcImage, dstImage, {}, srcImRect, dstImRect, {}, IM_SYNC);
        if (processStatus == IM_STATUS_SUCCESS) {
            isComposeOk = true;
        } else {
            LOGE(kTag, "improcess：%s", imStrError(processStatus));
        }
    }

    // 第 5 步 释放 handle：只是让 RGA 忘掉这两块内存，内存本身还归原来的主人
    releasebuffer_handle(srcHandle);
    releasebuffer_handle(dstHandle);
    return isComposeOk;
}
```

```cpp
#include "sink/nv12_file_writer.h"

#include <cerrno>  // errno
#include <cstdint> // uint8_t
#include <cstring> // strerror

#include "common/log.h"

static const char *const kTag = "Nv12Writer";

/**
 * @brief 创建输出文件
 * @param[in] filePath  文件路径
 * @return true = 成功；false = 失败
 * @note "wb"：只写、二进制，文件存在就清空
 */
bool Nv12FileWriter::open(const char *filePath) {
    filePtr.reset(fopen(filePath, "wb"));
    if (!filePtr) {
        LOGE(kTag, "打开 %s 失败：%s", filePath, strerror(errno));
        return false;
    }
    return true;
}

/**
 * @brief 写一帧
 * @param[in] picture  要写的画面
 * @return true = 成功；false = 失败
 * @note 第 1 步 拿到 CPU 能用的地址；第 2 步 写 Y 平面；第 3 步 写 UV 平面。一行一行写：每行只写 width 字节，
 *       跳过行尾的 stride 填充；UV 从第 verStride 行开始，不是第 height 行
 */
bool Nv12FileWriter::writePicture(const Nv12Picture &picture) {
    // 第 1 步 mpp_buffer_get_ptr：MPP 内部用 mmap 把这块 DRM buffer 映射到我们的进程，返回 CPU 能用的地址
    const uint8_t *frameStart = static_cast<const uint8_t *>(mpp_buffer_get_ptr(picture.mppBuf));
    if (!frameStart) {
        LOGE(kTag, "mpp_buffer_get_ptr 失败");
        return false;
    }
    // sync_begin：CPU 开始访问前调用。buffer 是带 cache 的话，丢掉 CPU cache 里的旧内容，读到 RGA 写进内存的新数据
    mpp_buffer_sync_begin(picture.mppBuf);

    // 第 2 步 Y 平面：height 行，每行 width 字节
    bool isWriteOk = true;
    for (int rowIndex = 0; rowIndex < picture.height && isWriteOk; ++rowIndex) {
        const uint8_t *rowStart = frameStart + static_cast<size_t>(rowIndex) * picture.horStride;
        isWriteOk = fwrite(rowStart, 1, picture.width, filePtr.get()) == static_cast<size_t>(picture.width);
    }

    // 第 3 步 UV 平面：从第 verStride 行开始，height / 2 行，每行 width 字节（U、V 交替）
    const uint8_t *uvStart = frameStart + static_cast<size_t>(picture.horStride) * picture.verStride;
    for (int rowIndex = 0; rowIndex < picture.height / 2 && isWriteOk; ++rowIndex) {
        const uint8_t *rowStart = uvStart + static_cast<size_t>(rowIndex) * picture.horStride;
        isWriteOk = fwrite(rowStart, 1, picture.width, filePtr.get()) == static_cast<size_t>(picture.width);
    }

    mpp_buffer_sync_end(picture.mppBuf); // CPU 访问结束，和 sync_begin 成对调用
    if (!isWriteOk) {
        LOGE(kTag, "fwrite 没写完：%s", strerror(errno));
        return false;
    }
    writtenFrameCount++;
    return true;
}
```

### 7.8 `src/pipeline/frame_queue.h`

和 Day 5 一模一样，可以直接复制 `day5_transcoder/src/pipeline/frame_queue.h`。

```cpp
//
// Created by DEV on 2026/11/15.
//
// FrameQueue：两个线程之间传解码帧的队列（生产者-消费者）
//
//   解码线程 ──push──→ [ 帧 | 帧 | 帧 | 帧 ] ──pop──→ 缩放编码线程
//
// 有容量上限：满了 push 就等着（背压），空了 pop 就等着。
// 队列里放的是 MppFramePtr：帧的所有权跟着走，谁手里拿着谁负责释放，不会漏、不会重复
//
#pragma once

#include <condition_variable>
#include <cstddef> // size_t
#include <deque>
#include <mutex>

#include "common/mpp_utils.h" // MppFramePtr

/** pop() 的结果 */
enum class PopResult {
    Frame,       // 取到一帧
    EndOfStream, // 生产者调用过 closeInput（不会再放帧了），而且队列也空了
    Aborted,     // 有一方出错调用了 abort，叫停整个流程
};

class FrameQueue {
public:
    /**
     * @brief 构造一个空队列
     * @param[in] requestedCapacityFrameCount  最多排几帧；排满了 push 就会等
     * @note 每排着一帧，就占着解码器内存池里的一块 buffer（池子一共 24 块），所以容量要比 24 小很多
     */
    explicit FrameQueue(size_t requestedCapacityFrameCount) : capacityFrameCount(requestedCapacityFrameCount) {}

    // 禁止拷贝：里面有 mutex（不能拷贝），而且帧只能有一个主人
    FrameQueue(const FrameQueue &) = delete;
    FrameQueue &operator=(const FrameQueue &) = delete;

    /**
     * @brief 生产者放一帧进去；队列满了就等，直到有空位或者被叫停
     * @param[in] framePtr  要放进去的帧，按值传入，所有权交给队列（调用方要写 std::move）
     * @return true = 放进去了；false = 流程被叫停（abort），帧没放进去，函数返回时随参数一起释放
     * @note 会阻塞：这就是"背压"，解码比编码快时，解码线程停在这里等
     */
    bool push(MppFramePtr framePtr);

    /**
     * @brief 消费者取一帧；队列空了就等，直到有帧、或者生产者说"没有了"、或者被叫停
     * @param[out] framePtr  取到的帧，所有权交给调用方；只有返回 PopResult::Frame 时才有效
     * @return PopResult::Frame = 取到一帧；EndOfStream = 帧都取完了；Aborted = 被叫停
     * @note 会阻塞
     */
    PopResult pop(MppFramePtr &framePtr);

    /**
     * @brief 生产者说"不会再 push 了"
     * @return 无
     * @note 消费者把队列里剩下的帧取完以后，pop 才返回 EndOfStream
     */
    void closeInput();

    /**
     * @brief 叫停：任何一方出错时调用，把正在 push / pop 里等的线程都叫醒，让两个线程都尽快退出
     * @return 无
     * @note 叫停以后队列里剩下的帧不取了，在队列析构时随 deque 一起释放
     */
    void abort();

    /**
     * @brief 队列里最多同时排过几帧
     * @return 帧数；等于容量说明队列满过，解码线程被背压挡住过
     * @note 两个线程都在改队列，读的时候也要加锁
     */
    size_t getMaxQueuedFrameCount() const;

private:
    const size_t capacityFrameCount;  // 最多排几帧
    mutable std::mutex mutex;         // 保护下面所有成员；mutable：const 函数里也要能加锁
    std::condition_variable notFull;  // "有空位了"：pop 取走一帧后通知，push 在它上面等
    std::condition_variable notEmpty; // "有帧了"：push 放进一帧后通知，pop 在它上面等
    std::deque<MppFramePtr> frames;   // 排着的帧，先进先出
    bool isInputClosed = false;       // 生产者调用过 closeInput
    bool isAborted = false;           // 有人调用过 abort
    size_t maxQueuedFrameCount = 0;   // 最多同时排过几帧
};
```

```cpp
#include <utility> // std::move

/**
 * @brief 放一帧进去，满了就等
 * @param[in] framePtr  要放进去的帧，所有权交给队列
 * @return true = 放进去了；false = 被叫停，帧没放进去
 * @note wait(锁, 条件) 等价于下面这个循环：
 *         while (!条件) {
 *             notFull.wait(lock); // 解锁 → 睡着 → 被叫醒 → 重新加锁 → 回到 while 再检查一次
 *         }
 *       条件一进来就成立：不睡，直接往下走。只有队列满了、又没被叫停时才真的停住。
 *       必须带条件：线程可能被"无缘无故"叫醒（虚假唤醒），醒来要再检查一次
 */
bool FrameQueue::push(MppFramePtr framePtr) {
    // unique_lock：加锁，离开作用域自动解锁；wait 要的就是 unique_lock，因为它要中途解锁、再加锁
    std::unique_lock<std::mutex> lock(mutex);
    // lambda 返回 true：立刻执行下一行；返回 false：停在这一行（睡着时锁是放开的），
    // 等 pop 或 abort 来 notify，醒来再算一次，算出 true 才往下走
    notFull.wait(lock, [this]() { return frames.size() < capacityFrameCount || isAborted; });
    if (isAborted) {
        return false;
    }
    frames.push_back(std::move(framePtr));
    if (frames.size() > maxQueuedFrameCount) {
        maxQueuedFrameCount = frames.size();
    }
    lock.unlock();         // 先解锁再通知：被叫醒的线程马上就能拿到锁
    notEmpty.notify_one(); // 叫醒一个在 pop 里等帧的线程（只有一个消费者）
    return true;
}

/**
 * @brief 取一帧，空了就等
 * @param[out] framePtr  取到的帧，所有权交给调用方
 * @return Frame = 取到一帧；EndOfStream = 生产者已 closeInput 并且帧取完了；Aborted = 被叫停
 * @note 生产者 closeInput 以后，队列里剩下的帧照样取，取完才返回 EndOfStream
 */
PopResult FrameQueue::pop(MppFramePtr &framePtr) {
    std::unique_lock<std::mutex> lock(mutex);
    // 有帧、或者生产者说没有了、或者被叫停，三者之一成立就往下走；否则睡着等 push / closeInput / abort 叫醒
    notEmpty.wait(lock, [this]() { return !frames.empty() || isInputClosed || isAborted; });
    if (isAborted) {
        return PopResult::Aborted;
    }
    if (frames.empty()) {
        return PopResult::EndOfStream; // 走到这里说明 isInputClosed，而且没有帧了
    }
    // std::move 只把帧的所有权转给了 framePtr，原来那个格子还留在 deque 里，里面是空的 unique_ptr。
    // pop_front 才把这个格子删掉。不删的话 frames.size() 不会变小，队列看起来一直是满的，push 永远等下去；
    // 下一次 front() 拿到的还是这个空格子
    framePtr = std::move(frames.front());
    frames.pop_front();
    lock.unlock();
    notFull.notify_one(); // 叫醒在 push 里等空位的生产者
    return PopResult::Frame;
}

/**
 * @brief 生产者说"不会再 push 了"
 * @return 无
 * @note 改完状态要 notify：消费者可能正睡在 pop 里，不叫醒它就永远等下去
 */
void FrameQueue::closeInput() {
    {
        std::lock_guard<std::mutex> lock(mutex); // lock_guard：只加锁、离开大括号解锁，不能中途解锁
        isInputClosed = true;
    }
    notEmpty.notify_all();
}

/**
 * @brief 叫停，叫醒所有在等的线程
 * @return 无
 * @note 两个条件变量都要 notify：生产者可能在 push 里等空位，消费者可能在 pop 里等帧
 */
void FrameQueue::abort() {
    {
        std::lock_guard<std::mutex> lock(mutex);
        isAborted = true;
    }
    notEmpty.notify_all();
    notFull.notify_all();
}

/**
 * @brief 最多同时排过几帧
 * @return 帧数
 * @note 两个线程都可能在用队列，读成员也要加锁
 */
size_t FrameQueue::getMaxQueuedFrameCount() const {
    std::lock_guard<std::mutex> lock(mutex);
    return maxQueuedFrameCount;
}
```

```cpp
#include "pipeline/decode_channel.h"

#include <utility> // std::move

/**
 * @brief 构造一路通道
 * @param[in] requestedChannelIndex             第几路
 * @param[in] requestedQueueCapacityFrameCount  队列容量
 * @return 无
 * @note 冒号后面是"成员初始化列表"：const 成员（channelIndex）和没有默认构造的成员（frameQueue）只能在这里初始化
 */
DecodeChannel::DecodeChannel(int requestedChannelIndex, size_t requestedQueueCapacityFrameCount) :
    channelIndex(requestedChannelIndex), logName("ch" + std::to_string(requestedChannelIndex)),
    frameQueue(requestedQueueCapacityFrameCount) {}

/**
 * @brief 打开码流文件，初始化解码器
 * @param[in] streamPath  码流文件路径
 * @param[in] codingType  码流格式
 * @return true = 成功；false = 失败
 * @note 日志名字 "ch0"、"ch1"…… 传给解码段和解码器，4 路的日志混在一起时能分清
 */
bool DecodeChannel::open(const char *streamPath, MppCodingType codingType) {
    return decodeStage.open(streamPath, codingType, logName.c_str());
}

/**
 * @brief 解码线程的函数体
 * @return 无
 * @note 第 1 步 解一帧；第 2 步 解完了就 closeInput，出错就 abort；第 3 步 放进队列，被叫停就退出
 */
void DecodeChannel::runDecodeLoop() {
    while (true) {
        // 第 1 步 解一帧
        MppFramePtr framePtr;
        const ReadFrameResult readFrameResult = decodeStage.readNextFrame(framePtr);

        // 第 2 步 解完了：告诉队列"不会再放了"，拼图线程取完剩下的帧就会拿到 EndOfStream
        if (readFrameResult == ReadFrameResult::EndOfStream) {
            frameQueue.closeInput();
            isDecodeOk = true;
            return;
        }
        if (readFrameResult == ReadFrameResult::Error) {
            frameQueue.abort(); // 叫醒可能等在 pop 里的拼图线程，让它知道出错了
            isDecodeOk = false;
            return;
        }

        // 第 3 步 放进队列。满了就在 push 里等（背压）；返回 false 说明拼图线程叫停了整个流程
        if (!frameQueue.push(std::move(framePtr))) {
            isDecodeOk = false;
            return;
        }
    }
}
```

```cpp
#pragma once

#include <memory> // std::unique_ptr
#include <vector>

#include "common/mpp_utils.h"
#include "common/nv12_picture.h"
#include "pipeline/decode_channel.h"

/** composeNextMosaic() 的结果 */
enum class ComposeResult {
    Mosaic,           // 拼好了一张大图
    AllChannelsEnded, // 所有通道都解完了，不会再有新的大图
    Aborted,          // 有一路出错叫停了整个流程
    Error,            // 拼图出错（RGA 失败，已打印原因）
};

/**
 * @brief 拼图段：从每一路的队列里各取一帧，用 RGA 缩放贴进大图里自己的格子
 * @note 大图只有一张（一块 buffer），每次 composeNextMosaic 都在它上面改。
 *       某一路解完了，它的格子不再更新，停在最后一帧
 */
class MosaicComposeStage {
public:
    /**
     * @brief 申请大图的 buffer，涂黑，算好每个格子的位置
     * @param[in] mosaicWidth   大图宽，单位像素，例如 1920
     * @param[in] mosaicHeight  大图高，单位像素，例如 1080
     * @param[in] requestedColumnCount  切成几列
     * @param[in] requestedRowCount     切成几行
     * @param[in] channelCount          一共几路；必须 ≤ 列数 × 行数
     * @return true = 成功；false = 失败（已打印原因）
     * @note 只能调用一次
     */
    bool open(int mosaicWidth, int mosaicHeight, int requestedColumnCount, int requestedRowCount, int channelCount);

    /**
     * @brief 拼下一张大图：每一路还没结束的通道各 pop 一帧，贴进它的格子
     * @param[in,out] channelPtrs  所有通道，下标就是格子编号；个数必须等于 open 时的 channelCount
     * @return Mosaic = 拼好一张；AllChannelsEnded = 都解完了；Aborted = 被叫停；Error = RGA 出错
     * @note 会阻塞：哪一路的帧还没解出来，就在它的 pop 里等。所以大图的速度跟着最慢的那一路走
     */
    ComposeResult composeNextMosaic(std::vector<std::unique_ptr<DecodeChannel>> &channelPtrs);

    /**
     * @brief 当前的大图
     * @return 大图的描述；buffer 归这个对象管
     * @note composeNextMosaic 返回 Mosaic 之后读；下一次 composeNextMosaic 会改它的内容
     */
    const Nv12Picture &getMosaicPicture() const { return mosaicPicture; }

    /**
     * @brief 一共拼了几张大图
     * @return 张数；4 路都解完时，等于帧数最多的那一路的帧数
     * @note 用来验收
     */
    int getComposedMosaicCount() const { return composedMosaicCount; }

    /**
     * @brief 某一路一共贴了几帧
     * @param[in] channelIndex  第几路
     * @return 帧数；正常结束时等于这一路解出来的帧数
     * @note 用来验收：每一帧都贴上了，一帧没丢
     */
    int getDrawnFrameCount(int channelIndex) const { return drawnFrameCounts[channelIndex]; }

private:
    /**
     * @brief 算第 cellIndex 个格子在大图里的位置：按行排，从左到右、从上到下
     * @param[in] cellIndex  格子编号，从 0 开始
     * @return 格子的矩形；x、y、宽、高都是偶数
     * @note 2 列 × 2 行、1920×1080 时：0 号 (0,0)，1 号 (960,0)，2 号 (0,540)，3 号 (960,540)，每格 960×540
     */
    PictureRect getCellRect(int cellIndex) const;

    MppBufferGroupPtr mosaicGroupPtr; // 大图 buffer 从这个组申请。必须声明在 mosaicBufferPtr 前面：
                                      // 成员按声明的反顺序析构，buffer 先还回去，组再释放

    std::vector<bool> isChannelEnded; // 每一路是不是已经解完；解完的不再 pop
    std::vector<int> drawnFrameCounts; // 每一路贴了几帧
    int composedMosaicCount = 0;      // 拼了几张大图
};
```

```cpp
#include "pipeline/mosaic_compose_stage.h"

#include "common/log.h"
#include "rga/rga_compositor.h"

static const char *const kTag = "MosaicCompose";

/**
 * @brief 申请大图、涂黑
 * @param[in] mosaicWidth   大图宽
 * @param[in] mosaicHeight  大图高
 * @param[in] requestedColumnCount  列数
 * @param[in] requestedRowCount     行数
 * @param[in] channelCount          路数
 * @return true = 成功；false = 失败
 * @note 第 1 步 检查参数；第 2 步 申请 buffer；第 3 步 整张涂黑
 */
bool MosaicComposeStage::open(int mosaicWidth, int mosaicHeight, int requestedColumnCount, int requestedRowCount,
                              int channelCount) {
    // 第 1 步 检查参数
    if (mosaicBufferPtr) {
        LOGE(kTag, "open 只能调用一次");
        return false;
    }
    if (channelCount > requestedColumnCount * requestedRowCount) {
        LOGE(kTag, "%d 路放不进 %d×%d 个格子", channelCount, requestedColumnCount, requestedRowCount);
        return false;
    }
    columnCount = requestedColumnCount;
    rowCount = requestedRowCount;
    isChannelEnded.assign(channelCount, false);
    drawnFrameCounts.assign(channelCount, 0);

    // 第 2 步 申请 buffer：DRM 类型的组，RGA 能通过 dma-buf fd 写它，编码器也能读它
    MppBufferGroup rawGroup = nullptr;
    MPP_CHECK(mpp_buffer_group_get_internal(&rawGroup, MPP_BUFFER_TYPE_DRM), false);
    mosaicGroupPtr.reset(rawGroup);
    mosaicPicture = makeAlignedNv12Picture(mosaicWidth, mosaicHeight);
    mosaicBufferPtr = allocNv12Buffer(mosaicGroupPtr.get(), mosaicPicture);
    if (!mosaicBufferPtr) {
        return false;
    }

    // 第 3 步 整张涂黑：新申请的 buffer 里是什么没有保证。没有画面的格子（比如只接了 3 路）就是黑的
    if (!fillNv12PictureBlack(mosaicPicture)) {
        return false;
    }
    LOGI(kTag, "大图 %dx%d，stride %dx%d，%d 列 × %d 行，每格 %dx%d", mosaicPicture.width, mosaicPicture.height,
         mosaicPicture.horStride, mosaicPicture.verStride, columnCount, rowCount, getCellRect(0).width,
         getCellRect(0).height);
    return true;
}

/**
 * @brief 拼下一张大图
 * @param[in,out] channelPtrs  所有通道
 * @return Mosaic / AllChannelsEnded / Aborted / Error
 * @note 每一路：第 1 步 pop 一帧；第 2 步 把帧描述成 Nv12Picture；第 3 步 RGA 缩放贴进格子；第 4 步 帧释放，buffer 还给这一路的解码器
 */
ComposeResult MosaicComposeStage::composeNextMosaic(std::vector<std::unique_ptr<DecodeChannel>> &channelPtrs) {
    bool hasDrawnAnyCell = false;
    for (std::unique_ptr<DecodeChannel> &channelPtr : channelPtrs) {
        const int channelIndex = channelPtr->getChannelIndex();
        if (isChannelEnded[channelIndex]) {
            continue; // 这一路解完了，格子停在最后一帧
        }

        // 第 1 步 pop 一帧。这一路的帧还没解出来，就在这里等
        MppFramePtr framePtr;
        const PopResult popResult = channelPtr->getFrameQueue().pop(framePtr);
        if (popResult == PopResult::Aborted) {
            return ComposeResult::Aborted;
        }
        if (popResult == PopResult::EndOfStream) {
            isChannelEnded[channelIndex] = true;
            LOGI(kTag, "ch%d 解完了（贴了 %d 帧），格子停在最后一帧", channelIndex, drawnFrameCounts[channelIndex]);
            continue;
        }

        // 第 2 步 描述成 Nv12Picture：宽高、stride 用这一帧自己的，每一路可能都不一样
        Nv12Picture decodedPicture;
        if (!describeDecodedFrame(framePtr.get(), decodedPicture)) {
            return ComposeResult::Error;
        }

        // 第 3 步 RGA 缩放贴进格子
        if (!resizeNv12IntoRectByRga(decodedPicture, mosaicPicture, getCellRect(channelIndex))) {
            return ComposeResult::Error;
        }
        drawnFrameCounts[channelIndex]++;
        hasDrawnAnyCell = true;
        // 第 4 步 framePtr 在这一圈结束时析构：RGA 已经读完（同步调用），buffer 马上回到这一路解码器的内存池
    }

    if (!hasDrawnAnyCell) {
        return ComposeResult::AllChannelsEnded; // 这一圈每一路都是"已经解完"，没有新画面
    }
    composedMosaicCount++;
    return ComposeResult::Mosaic;
}

/**
 * @brief 算格子位置
 * @param[in] cellIndex  格子编号
 * @return 格子的矩形
 * @note & ~1：把最低位清零，变成偶数。RGA 要求 NV12 的矩形 x、y、宽、高都是偶数
 */
PictureRect MosaicComposeStage::getCellRect(int cellIndex) const {
    const int cellWidth = (mosaicPicture.width / columnCount) & ~1;
    const int cellHeight = (mosaicPicture.height / rowCount) & ~1;
    const int columnIndex = cellIndex % columnCount; // 第几列
    const int rowIndex = cellIndex / columnCount;    // 第几行
    return {columnIndex * cellWidth, rowIndex * cellHeight, cellWidth, cellHeight};
}
```

```cpp
}

/**
 * @brief 打印每一路的结果
 * @param[in] channelPtrs   所有通道
 * @param[in] composeStage  拼图段
 * @param[in] tag           日志标签
 * @return true = 全部正常；false = 有一路不正常
 * @note "解出的帧全部贴上了"：贴的帧数 == 解出的帧数，说明队列里一帧都没丢
 */
bool printChannelResults(const std::vector<std::unique_ptr<DecodeChannel>> &channelPtrs,
                         const MosaicComposeStage &composeStage, const char *tag) {
    bool isAllOk = true;
    for (const std::unique_ptr<DecodeChannel> &channelPtr : channelPtrs) {
        const int channelIndex = channelPtr->getChannelIndex();
        const DecodeStage &decodeStage = channelPtr->getDecodeStage();
        const int drawnFrameCount = composeStage.getDrawnFrameCount(channelIndex);
        LOGI(tag, "ch%d %s：解码%s，正常帧 %d，错误帧 %d，贴进大图 %d 帧，队列最多排过 %zu 帧", channelIndex,
             kChannelInputs[channelIndex].streamPath, channelPtr->isDecodeLoopOk() ? "正常" : "出错",
             decodeStage.getDecodedFrameCount(), decodeStage.getErrorFrameCount(), drawnFrameCount,
             channelPtr->getFrameQueue().getMaxQueuedFrameCount());
        if (!channelPtr->isDecodeLoopOk() || decodeStage.getErrorFrameCount() > 0 ||
            drawnFrameCount != decodeStage.getDecodedFrameCount()) {
            isAllOk = false;
        }
    }
    return isAllOk;
}
```

### 7.17 `src/app/m2_compose_mosaic.cpp`

```cpp
#include "app/m2_compose_mosaic.h"

#include <memory> // std::unique_ptr
#include <thread>
#include <vector>

#include "app/app_config.h"
#include "app/channel_helpers.h"
#include "common/log.h"
#include "common/time_utils.h"
#include "pipeline/decode_channel.h"
#include "pipeline/mosaic_compose_stage.h"
#include "sink/nv12_file_writer.h"

static const char *const kTag = "M2";

/**
 * @brief 这张大图要不要存下来
 * @param[in] mosaicIndex  第几张大图，从 0 开始
 * @return true = 在 kM2SnapshotMosaicIndexes 里，要存
 * @note 范围 for 可以直接遍历 C 数组
 */
static bool isSnapshotMosaic(int mosaicIndex) {
    for (const int snapshotIndex : kM2SnapshotMosaicIndexes) {
        if (snapshotIndex == mosaicIndex) {
            return true;
        }
    }
    return false;
}

/**
 * @brief 拼图循环：一张一张拼大图，遇到要存的就写进文件，直到所有通道都解完
 * @param[in,out] channelPtrs     所有通道
 * @param[in,out] composeStage    拼图段
 * @param[in,out] snapshotWriter  存大图的文件
 * @return true = 拼到所有通道都解完；false = 出错或被叫停
 * @note 在调用它的线程（主线程）里跑。出错时叫停所有通道，让解码线程都退出
 */
static bool runComposeLoop(std::vector<std::unique_ptr<DecodeChannel>> &channelPtrs,
                           MosaicComposeStage &composeStage, Nv12FileWriter &snapshotWriter) {
    while (true) {
        const ComposeResult composeResult = composeStage.composeNextMosaic(channelPtrs);
        if (composeResult == ComposeResult::AllChannelsEnded) {
            return true;
        }
        if (composeResult != ComposeResult::Mosaic) {
            abortAllChannels(channelPtrs); // Aborted：有一路出错了；Error：RGA 出错。都要叫停其他通道
            return false;
        }

        const int mosaicIndex = composeStage.getComposedMosaicCount() - 1;
        if (isSnapshotMosaic(mosaicIndex)) {
            if (!snapshotWriter.writePicture(composeStage.getMosaicPicture())) {
                abortAllChannels(channelPtrs);
                return false;
            }
            LOGI(kTag, "存下第 %d 张大图", mosaicIndex);
        }
    }
}

/**
 * @brief M2：4 路解码 + RGA 拼成 2×2 大图
 * @return 0 = 成功；1 = 失败
 * @note 第 1 步 打开 4 路通道；第 2 步 打开拼图段和抓图文件；第 3 步 每路起一个解码线程；
 *       第 4 步 主线程拼图；第 5 步 等解码线程结束；第 6 步 打印结果
 */
int runM2ComposeMosaic() {
    // 第 1 步 打开 4 路通道
    std::vector<std::unique_ptr<DecodeChannel>> channelPtrs;
    if (!openAllChannels(channelPtrs)) {
        return 1;
    }

    // 第 2 步 打开拼图段和抓图文件
    MosaicComposeStage composeStage;
    if (!composeStage.open(kMosaicWidth, kMosaicHeight, kMosaicColumnCount, kMosaicRowCount, kChannelCount)) {
        return 1;
    }
    Nv12FileWriter snapshotWriter;
    if (!snapshotWriter.open(kM2SnapshotPath)) {
        return 1;
    }

    // 第 3 步 每路起一个解码线程。[&channel]：按引用捕获这一路的 DecodeChannel，线程里调用它的 runDecodeLoop
    const double startMs = getNowMs();
    std::vector<std::thread> decodeThreads;
    for (std::unique_ptr<DecodeChannel> &channelPtr : channelPtrs) {
        DecodeChannel &channel = *channelPtr;
        decodeThreads.emplace_back([&channel] { channel.runDecodeLoop(); });
    }

    // 第 4 步 主线程拼图（不另起线程：主线程本来也要等着，正好用它来拼）
    const bool isComposeOk = runComposeLoop(channelPtrs, composeStage, snapshotWriter);

    // 第 5 步 等解码线程结束。拼图出错时已经 abort 了所有队列，解码线程很快会退出
    for (std::thread &decodeThread : decodeThreads) {
        decodeThread.join();
    }
    const double elapsedMs = getNowMs() - startMs;

    // 第 6 步 打印结果
    const bool isChannelsOk = printChannelResults(channelPtrs, composeStage, kTag);
    const int composedMosaicCount = composeStage.getComposedMosaicCount();
    LOGI(kTag, "拼了 %d 张大图，用时 %.0f ms，%.1f 张/秒", composedMosaicCount, elapsedMs,
         elapsedMs > 0 ? composedMosaicCount * 1000.0 / elapsedMs : 0.0);
    LOGI(kTag, "存了 %d 张大图到 %s", snapshotWriter.getWrittenFrameCount(), kM2SnapshotPath);
    if (!isComposeOk || !isChannelsOk) {
        LOGE(kTag, "失败：拼图%s，通道%s", isComposeOk ? "正常" : "出错", isChannelsOk ? "正常" : "不正常");
        return 1;
    }
    return 0;
}
```

```cpp
#include <cstring> // strcmp

#include "app/m1_decode_channels.h"

 * @param[in] argc  参数个数（包括程序名）
 * @param[in] argv  参数；argv[1] 是里程碑名字："m1"、"m2"，不写默认 "m2"

 * @note main 只做分发，不放业务逻辑

        return runM1DecodeChannels();

    if (strcmp(milestoneName, "m2") == 0) {
        return runM2ComposeMosaic();

    LOGE(kTag, "用法：%s m1 | m2", argv[0]);
    return 1;
}
```
