## 2. N1 → N9、N11、N7、N12（码流来源）

```cpp
struct AccessUnit {                         // 一帧：同一个时间戳的所有 NAL
    std::vector<std::vector<uint8_t>> nalUnits; // 不带起始码
    bool isKeyFrame = false;
    int64_t captureTimeUs = 0;              // 摄像头源用；文件源为 0
};
enum class SourceReadResult { Ok, EndOfStream, Error };
class AccessUnitSource {                    // 实现：FileAccessUnitSource（文件，按 30 fps 节流）、CameraAccessUnitSource（Day 4 摄像头 + MppEncoder）
public:
    virtual ~AccessUnitSource() = default;
    virtual VideoCodec getCodec() const = 0;
    virtual const ParameterSets &getParameterSets() const = 0;
    virtual bool isLiveSource() const = 0;
    virtual SourceReadResult readNextAccessUnit(AccessUnit &outputUnit) = 0;
};
```

推流类阶段（N9 PS、N11 RTMP/FLV、N7 HTTP-FLV/HLS、N12 WebRTC）都从 `AccessUnitSource` 取帧，自己按协议封装。

## 3. N2 → N3、N4、N5、N8、N10（接收端）

```cpp
struct StreamInfo {                         // 一次连接的码流信息（重连后可能变）
    VideoCodec codec = VideoCodec::H264;
    int clockRateHz = 90000;
    std::vector<uint8_t> vps, sps, pps;     // 来自 SDP，不带起始码
};
struct EncodedFrame {                       // 一帧码流
    std::vector<uint8_t> annexBData;        // 每个 NAL 前面都有 00 00 00 01
    uint32_t rtpTimestamp = 0;
    int64_t extendedRtpTimestamp = 0;       // 展开成 64 位，单调递增；PTS = 它（time_base 1/90000）
    bool isKeyFrame = false;                // 含 IDR（H.264 type 5；H.265 type 16～21）
    int64_t frameIndex = 0;                 // 这次连接里的第几帧
};
enum class ReceiveResult { FrameReady, StreamEnded, Timeout, Error };
class RtspReceiver {
public:
    bool connectAndPlay(const std::string &requestedUrl);  // URL 可带 用户:密码@（Digest 鉴权，见第 5 节）
    ReceiveResult receiveNextFrame(EncodedFrame &outputFrame);
    const StreamInfo &getStreamInfo() const;
    void teardownAndClose();
    int getLostPacketCount() const;
};
enum class ReconnectingReceiveResult { FrameReady, StreamRestarted, Stopped };
class ReconnectingReceiver {
public:
    ReconnectingReceiver(std::string requestedUrl, int requestedReceiveTimeoutMs, int requestedMaxBackoffMs);
    ReconnectingReceiveResult receiveNextFrame(EncodedFrame &outputFrame); // StreamRestarted：要重建解码器 / 开新录像文件
    const StreamInfo &getStreamInfo() const;
    void requestStop();
    int getReconnectCount() const;
};
class StreamDecodeStage {                   // EncodedFrame → MPP 解码（内部用 Day 6 的 MppDecoder）
public:
    bool open(VideoCodec codec, const char *requestedLogName);
    bool decodeFrame(const EncodedFrame &encodedFrame);
    bool finishAndDrain();
    void resetDecoder();
    int getDecodedFrameCount() const;
    int getErrorFrameCount() const;
};
MppCodingType toMppCodingType(VideoCodec codec);
```

- N2 是单线程、类不加锁；N5 在外面加线程和队列，一帧用 `std::shared_ptr<const EncodedFrame>` 同时给录像和解码。
- 后面阶段里出现的 `AccessUnit`（N10 计划里的 annexBData 版）、`VideoStreamInfo`、`RtspClient::readAccessUnit`、`readEncodedFrame` 都改成上面的 `EncodedFrame`、`StreamInfo`、`RtspReceiver::receiveNextFrame`。

## 4.1 第 3 节的两处补充（N3、N5 计划提出，Claude 定，N2 代码照做）

- `StreamInfo` 加 `int widthPixels = 0, heightPixels = 0;`：H.264 用 N2 的 `parseH264Sps` 填；H.265 暂不解析，保持 0（调用方用默认值）。
- `StreamDecodeStage` 加解码帧出口：`void setFrameOutput(std::function<void(MppFramePtr)> requestedFrameOutput);`，设置了就把每个正常帧交出去（所有权跟着走），没设置就像现在一样只计数后释放。N5 用它接到拼图队列。
- H.265 关键帧按 IRAP：NAL type 16～21（BLA 16～18、IDR 19～20、CRA 21），H.265 规范定义；N2 周计划写的 19/20 只是 IDR。

## 5. 补给 N2 的两项（Claude 定，给 N8 接真 IPC 用）

- **H.265 解包**：N1 M3 已经发 H.265（FU 类型 49），N2 的 `RtpDepacketizer` 同时支持 H.264 FU-A 和 H.265 FU。
- **RTSP Digest 鉴权**：URL 带 `user:pass@` 时，收到 401 按 RFC 2617 算 Digest 重发。MD5 用 OpenSSL（sysroot 里有 libcrypto）。代码放 N2 的 `rtsp/rtsp_digest_auth.h/.cpp`，N9 的 SIP Digest 复用同一份 MD5 函数。
- 这两项放在 N2 第 09 周快照（M4）之后，作为“M5 接真 IPC 的准备”，用户读懂即可，不在手敲清单里。
