**Mac 实测（2026-11-20）**
- letterbox：1920×1080 → 640×640 得 scale 1/3、缩放后 640×360、上补边 140；拉伸 scaleY = 640/1080；810×1080 竖图左补边 80。模型坐标 → 原图坐标换算、超出灰边的部分夹到 [0, 1079]。

**Mac 实测（2026-11-20，FFmpeg 4.4）**
- 预录缓冲：30 秒假数据（30 fps、GOP 60），留 10 秒 → 缓冲在 [10, 12) 秒，第一帧是 IDR；`takeAll` 后下一个关键帧之前的帧不收。
- 状态机：有人 / 没人 / 有人不触发；连续 3 次触发，开始时间取这一串的第一次；PostRoll 期间又有人回到 Recording；最后见到人 10 秒后才关；人一直在时到最长时长强制关。
- 只留最新一帧的槽：连放 3 个丢 2 个，取到的是最后一个；关了以后 take 返回 false。
- NV12 画框（64×32，stride 80）：奇数坐标对齐到偶数、线宽 2、UV 写对位置、框外和 stride 多出的字节不动、超出画面的框被裁掉。
- events 表：插入 3 条，按通道、开始时间查出 2 条。
- 端到端（`aaa.264` + 每 3 帧给一次假检测结果）：
  - 20～25 秒有人 → 1 个事件，预录 321 帧（10.7 秒），文件 763 帧、25.4 秒（≈ 9.5 → 35 秒）；`ffmpeg -v error -f null` 0 行，第一帧 key_frame=1；记录时长和文件时长差 33 ms。
  - 20～25、30～32、50～52 秒有人 → 2 个事件：第 1 个 32.4 秒（中间间隔 5 秒没切开），第 2 个 20.3 秒（录到文件结束，`closeOpenEvent` 收尾），同一秒开的文件名加了 `_1`。

**和计划不一样的地方**
- 输入不用 N2 的 `RtspClient`（N2 跳过），用 N3 的 `FfmpegFrameSource`（文件或 `rtsp://` 同一份代码；裸流文件按 30 fps 实时放，可以循环放几遍）。码流类型是 `EncodedFrame` / `StreamInfo`（`0_跨阶段接口.md`），不是计划里的 `AccessUnit` / `VideoStreamInfo`。从 N3 复制了 `common/encoded_frame.h`、`video_codec.h`、`annexb_utils`、`ffmpeg_utils.h`、`source/ffmpeg_frame_source`、`storage/mp4_file_writer`、`storage/mp4_probe`。
- 事件文件用 N3 的 `Mp4FileWriter`，默认 fMP4（断电时已写的片段也能播）。
- 预录缓冲按 90 kHz 时间戳算（码流自带的单位）；状态机、检测结果用微秒（`ptsUs = 90 kHz × 100 / 9`）。
- `MppDecoder::feed` 加了 `ptsUs` 参数（`mpp_packet_set_pts`），推断解码器会把它带到输出帧上（split_parse 开着），**上板确认**：日志里状态变化的 pts 应该和码流时间对得上；对不上时状态机会一直不关事件。
- `EventStateConfig` 多了 `maxEventDurationUs`（10 分钟强制切开）。事件确认后迟迟打不开文件、又到了关闭时间，就直接作废，不让状态卡住。
- 事件记录的结束时间 = 开始 + 文件时长（不取关文件时的墙钟），文件输入快放时也对得上。
- `drawNv12Rectangle` 拆成不依赖 MPP 的 `Nv12PlaneView` 版（Mac 能测）+ `overlay/nv12_frame_overlay` 的 `drawDetectionBoxesOnFrame(MppFrame, ...)`（前后 cache 同步）。绿色、红色的 YUV 值按 BT.601 有限范围公式算的，颜色对不对上板看截图。
- `LatestFrameSlot` 是模板 `LatestSlot<T>` 的别名（Mac 测试用 `unique_ptr<int>`）。
- `DetectStage` 两个 `start`（FrameQueue / LatestFrameSlot），回调改成 `DetectedFrameCallback(MppFrame, const DetectionResult &)`，可以直接在帧上画框；M1 的回调跟着改了签名。
- 计划的板上自测 `m2test` 没做成单独命令，预录缓冲等都在 Mac 单测里测了。
- Ctrl+C（SIGINT / SIGTERM）：停接收 → 关槽 → 等检测线程 → 正在录的事件收尾写记录。

## 第 18 周 M3 YOLOv8 和 NPU 多核（2026-11-20）

**状态**：交叉编译 0 警告（clean 重编）；Mac 单测 106 项全过（含 M0～M2 的 84 项）；**未上板**；`convert_yolov8.sh` 没跑。

**Mac 实测（2026-11-20）**
- DFL：16 个 bin 全相等 → 7.5；单峰在 bin 3 → 3.0；bin 2、4 各一半 → 3.0；一个 bin 是 1000 也不溢出（先减最大值再 exp）。
- 造的 int8 输出（3 个尺度，格子 8/4/2，stride 8/16/32）：自己的解码和 model_zoo `process_i8`（原样复制）结果一致：2 个对 2 个，全部配上，误差 < 0.01 像素；分数和低于阈值的格子两边都跳过；去掉分数和（6 输出的模型）两边都变成 3 个。框坐标和手算对得上（bin 不是严格 one-hot，stride 32 时偏约 0.15 像素）。

**和计划不一样的地方**
- YOLOv8 参考代码：rknn_model_zoo 没有下载，用正点原子网盘 `01、AI例程/01、linux6.1AI例程/01、源码/10_yolov8/yolov8.zip` 的 `cpp/postprocess.cc`（就是 model_zoo 的那份）。`process_i8` 等复制到 `src/third_party/rknn_model_zoo_yolov8/`，只用来对比。
- 那个 zip 里自带 `model/yolov8.rknn`，`strings` 看是 **toolkit 2.3.2** 转的（2025-04-07）；zip 里还有 `librknnrt.so` **2.3.2**。板子 runtime 是 2.0.0b0，推断加载会失败——正好是第 18 周问题 3 的素材。三条路：① 跑 `convert_yolov8.sh`（model_zoo v2.0.0 + toolkit 2.0.0b0）；② `V8_MODEL=<zip 里的 yolov8.rknn> PUSH_SDK_RKNNRT=1 RKNNRT_FILE=<zip 里的 aarch64/librknnrt.so>` 换成 2.3.2 的 runtime（驱动 0.9.6 能不能配 2.3.2 runtime：推断，没核对）；③ 只用 v5 先把多核表做了。
- 计划的 `decodeYolov8Outputs(const RknnModel &, ...)` 换成 `ObjectDetector::buildYolov8OutputBranches` + `decodeYolov8OutputBranches` / `runYolov8PostProcess`（和 v5 同样拆法，Mac 能测）。6 输出（没有分数和）和 9 输出都支持。
- `DetectWorkerPool::init(path, config, std::vector<rknn_core_mask>)`：一个元素一个 worker，不用计划的 `requestedWorkerCount`。回调是 `DetectionCallback`（只有结果、不带帧：帧检测完立刻还给解码器，不因为等排序多占 buffer）。结果按取帧顺序排好再回调，打印“排序最多压了几个”。
- `ObjectDetector::initSharingModel(source)`（`rknn_dup_context`）+ `setNpuCoreMask`。pool 析构时先销毁复制出来的 context、源最后（推断有必要）。
- 多个检测线程同时调 RGA（每个 detector 一个目标 buffer）：推断 librga 的 im2d 可以多线程用，上板看有没有报错。
- 多了“只解码不检测”的吞吐作为基准：检测吞吐接近它时，瓶颈在解码，不能算到 NPU 头上。
- 故障注入做成 `m3fault`（v5 模型 + bus.jpg）：`swap` 绕过 stride 检查、像 demo 那样按下标认 stride；`zp` 把 zeroPoint 当 0；`norelease` 连跑 300 次不 release，每 50 次打印 VmRSS。真把输出顺序弄反时 `buildYolov5OutputTensors` 会直接报 stride 不对。
- m1、m2 还是只用 YOLOv5（`ObjectDetectorConfig.yoloVersion` 默认 V5）；N5 要用 v8 时设 `yoloVersion = YoloVersion::V8`。
- 模拟面试、问题案例库、README 第 8 节标完成：都是文档，按约定不写。
