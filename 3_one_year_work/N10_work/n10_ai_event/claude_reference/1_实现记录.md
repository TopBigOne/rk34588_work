## 第 16 周 M1 检测接入流水线（2026-11-20）

**状态**：交叉编译 0 警告（clean 重编；新增链接 `rockchip_mpp`、`rga`）；Mac 单测 `n10_mac_tests` 33 项全过；**未上板**（板子还没接，`adb devices` 仍只有三星手机）。

**Mac 实测（2026-11-20）**
- letterbox：1920×1080 → 640×640 得 scale 1/3、缩放后 640×360、上补边 140；拉伸 scaleY = 640/1080；810×1080 竖图左补边 80。模型坐标 → 原图坐标换算、超出灰边的部分夹到 [0, 1079]。
- CPU letterbox：4×2 → 4×4，上下各 1 行 114，中间原样。
- NMS：同类 IoU 0.82 的删掉，不同类别完全重合的两个都留，结果按分数降序。
- 造的 int8 输出（zp = -128，scale = 1/255）和 demo `post_process` 对比：只有 person 时自己 3 个、demo 3 个，全部配上，最大误差 2 像素（误差来自 demo 在模型坐标里先取整再除以 scale）。
- **demo 的 NMS 会跨类别抑制**：相邻格子一个 person、一个 bicycle（IoU 约 0.66），自己的留 2 个，demo 只留 1 个。读 `postprocess.cc` 的 `nms()`：类别判断写的是 `classIds[i]`（排序后的位置），应该是 `classIds[n]` / `classIds[m]`（原始下标）。所以 bus.jpg 上如果有不同类别的框重叠，m1cmp 会报“不一致”，属于预期。

**和计划不一样的地方**
- 后处理中间结果用 `npu/candidate_object.h` 的 `CandidateObject`（模型坐标、float），不用计划写的 `std::vector<DetectedObject>`：全程 float，最后一步才换算成原图整数坐标。
- `LetterboxInfo` 是 `scaleX`、`scaleY`、`resizedWidth/Height`、`padLeftPixels`、`padTopPixels`（计划只有一个 `scale`，拉伸模式需要两个）。
- 后处理拆成不依赖 RKNN 的 `decodeYolov5OutputTensors(const std::vector<Yolov5OutputTensor> &, ...)`，再加一个总入口 `runYolov5PostProcess`（解码 → NMS → 换算），这样 Mac 能测；计划里的 `decodeYolov5Outputs(const RknnModel &, ...)` 换成 `ObjectDetector::buildYolov5OutputTensors(model, tensors)` + 它。
- `TensorQuantInfo` 挪到 `npu/tensor_quant_info.h`（Mac 上没有 `rknn_api.h`）。`RknnModel` 加了 `getOutputDims`，检测器用它确认输出是 [1, 255, H, W] 且 stride 按 8 / 16 / 32 排，不对就报错，不猜。
- `ObjectDetectorConfig`：`yoloVersion`、`isLetterboxEnabled`、两个阈值、`letterboxPadValue`；`init(path, config)`。
- `DetectStage::start(FrameQueue &, ObjectDetector &, DetectionCallback)`（M1 用阻塞队列；M2 换 `LatestFrameSlot`）。M1 里主线程直接当解码线程，没有单独的解码线程对象。
- pts：用 N0 `DecodeStage::setPtsFrameRate(30)` 按帧号打（计划风险 7 绕过去了，没验证解码器会不会自己带 pts）。
- 多了 `m1cmp`：同一张图、同一次推理输出，自己的后处理和 demo 的各跑一遍并配对比较（计划 M1 验收第 2 条）。`m0` 改成走 `app/image_input` + `runDemoPostProcess`，行为不变。
- `postprocess.cc` 第 3 处改动：标签路径加 `#ifndef`，Mac 单测用 `-D` 换成 `src/tests/coco_80_labels_list.txt`（从 SDK 复制）。
- RGA 前处理后 CPU 读 RGB：`mpp_buffer_sync_begin` + `sync_end` 一对（推断这样对只读足够，上板看 .rgb 确认）。

**待上板**
