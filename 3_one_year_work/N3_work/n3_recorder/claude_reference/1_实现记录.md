# N3 实现记录

## 第 10 周 M1 转封装（2026-11-20）

**状态**：交叉编译 0 警告；Mac 构建 + `n3_mac_tests` 全部通过；Mac 端到端（`aaa.264` → MP4）通过；**未上板**；RTSP 输入没跑过（SRS 没编译）。

**Mac 实测（2026-11-20，FFmpeg 4.4）**
- `n3_mac_tests`：aaa.264 读出 1803 帧、36 个关键帧、第一帧是关键帧、最后时间戳 5406000；写 90 帧 MP4 读回 nb_frames=90、时长 3.000 秒、extradata[0]=1（封装器把 Annex-B 转成了 avcC）。
- `n3_recorder m1 aaa.264 m1_ch0.mp4`：1800 帧，58425434 字节，用时 162 ms；ffprobe `h264 1920x1080 avg_frame_rate=30/1 nb_frames=1800 duration=60.000000`；第一帧 key_frame=1；`ffmpeg -f null` 0 输出；`-ss 30` 抽帧 0 报错；顶层 box `ftyp free mdat moov`。
- 写头后 `time_base` 仍是 1/90000（计划第 5 节“推断大概率保持不变”，Mac 4.4 上核对了）。
- 计划第 5 节“要先确认的事实 1”（Annex-B 转 AVCC 由谁做），Mac 4.4 上用 `tools/mp4_box_walker` 核对了：`avcC` 的 configurationVersion=1，`mdat` 第一帧开头是 `00 00 00 33`（4 字节长度），不是起始码，说明是 libavformat 的 mp4 封装器转的。板子 4.4.1 推断一样。mvhd 时长 60.000 秒。

**和计划不一样的地方**
- N1、N2 跳过（见计划开头“变更”）：没有 `rtsp/`；输入是 `source/ffmpeg_frame_source`（libavformat，文件或 `rtsp://` 同一份代码），返回 `ReceiveResult`（沿用接口文档里的枚举名）。
- `StreamInfo` 加了 `width`、`height`（libavformat 直接给出，不用 SPS 解析器）。
- 加了 `common/annexb_utils`：切 NAL、判断关键帧（`EncodedFrame::isKeyFrame` 按 NAL 类型算，不信 AV_PKT_FLAG_KEY）、从 extradata 挑 VPS/SPS/PPS。
- `ffmpeg_utils.h` 拆成输入 / 输出两种上下文删除器：输出上下文要用 `avformat_free_context`，不能用 `avformat_close_input`。
- M1 录满 60 秒就停（RTSP 不会自己结束），所以 aaa.264 的 1803 帧只写了 1800 帧（第 1800 帧 pts = 60.0 秒）。
- 每帧 duration 按和上一帧的间隔填，否则最后一帧时长是 0。
- 加了 `tools/mp4_box_walker.cpp`（计划里第 14 周快照才有，M1 验收要用，提前放进来）。
- `start_fake_ipc_on_board.sh` 换成 `start_rtsp_source_on_mac.sh`（SRS + ffmpeg 推流 + `adb reverse`）。
