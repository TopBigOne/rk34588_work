**Mac 实测（2026-11-20，FFmpeg 4.4）**
- `n3_mac_tests`：aaa.264 读出 1803 帧、36 个关键帧、第一帧是关键帧、最后时间戳 5406000；写 90 帧 MP4 读回 nb_frames=90、时长 3.000 秒、extradata[0]=1（封装器把 Annex-B 转成了 avcC）。
- `n3_recorder m1 aaa.264 m1_ch0.mp4`：1800 帧，58425434 字节，用时 162 ms；ffprobe `h264 1920x1080 avg_frame_rate=30/1 nb_frames=1800 duration=60.000000`；第一帧 key_frame=1；`ffmpeg -f null` 0 输出；`-ss 30` 抽帧 0 报错；顶层 box `ftyp free mdat moov`。

- `ffmpeg_utils.h` 拆成输入 / 输出两种上下文删除器：输出上下文要用 `avformat_free_context`，不能用 `avformat_close_input`。
- M1 录满 60 秒就停（RTSP 不会自己结束），所以 aaa.264 的 1803 帧只写了 1800 帧（第 1800 帧 pts = 60.0 秒）。
- 每帧 duration 按和上一帧的间隔填，否则最后一帧时长是 0。
- 加了 `tools/mp4_box_walker.cpp`（计划里第 14 周快照才有，M1 验收要用，提前放进来）。
- `start_fake_ipc_on_board.sh` 换成 `start_rtsp_source_on_mac.sh`（SRS + ffmpeg 推流 + `adb reverse`）。

## 第 11 周 M2 录像分段（2026-11-20）

**状态**：交叉编译 0 警告；Mac 构建 + `n3_mac_tests` 全部通过；Mac 端到端（aaa.264 循环 10 遍 → 10 分钟、每段 60 秒）通过；**未上板**。

**Mac 实测（2026-11-20）**
- `n3_mac_tests` 新增：录像路径 `ch2/2027-02-03/14-05-00.mp4`、同名加 `_1`；30 秒 / 每段 5 秒 → 6 个文件，每段首帧都是关键帧、时长 5.133～5.567 秒，帧数合计 = 写入帧数 = 900；时间戳倒退 → 丢 5 帧（到下一个 IDR）、开新段，共 2 个文件。
- `n3_recorder m2 aaa.264 <根>`：收到 18000 帧（输入循环 9 次），开头丢 0 帧，写入 18000 帧，10 个文件，用时 1805 ms。计划的验收命令：每个文件首帧 key_frame=1；`nb_read_frames` 加起来 18000；前 9 个文件都是 60.100 秒（aaa.264 每 60.1 秒循环一次，循环的开头正好是 IDR），最后一个 59.100 秒（录满 600 秒截止）；10 个文件 `ffmpeg -v error -f null` 共 0 行输出。

**和计划不一样的地方**
- **段首的墙上时间不是写这一帧时取的系统时间**，而是“锚点 + 码流时间差”：第一帧（和断流后第一帧）取一次系统时间当锚点，之后段首时间 = 锚点 + (段首帧时间戳 − 锚点帧时间戳) / 90。原因：读文件比实时快很多（10 分钟 1.8 秒录完），直接取系统时间文件名会撞在同一秒；而且这样文件名和 PTS 对得上，N4 按时间回放更准。RTSP 实时输入时两种算法结果差不多（推断）。
- 同一秒已经有文件时加 `_1`、`_2`（计划没写）。
- `FfmpegFrameSource` 加了 `setShouldLoopRawFile`：裸流读完重新打开，时间戳接着涨（代替计划里“N1 循环发送且 RTP 时间戳接着涨”）。
- `SegmentRecorder::writeFrame` 自己检测时间戳倒退并 `markDiscontinuity()`；断流后到下一个 IDR 之前的帧丢掉，不写进旧段。

**待上板**

- 板子时间和时区：`adb shell date` 和 Mac 对一下；文件名应该是北京时间（脚本先 `. /etc/profile`）。

**给后面阶段的接口**

## 第 14 周 M4 循环覆盖和断电保护（2026-11-20，N3 收尾）

**状态**：交叉编译 0 警告；Mac 构建 + `n3_mac_tests` 全部通过；Mac 端到端（配额、kill -9、启动修复、故障注入 2 个）通过；**未上板**。**N5、N10 复制的就是这一份快照。**

**Mac 实测（2026-11-20）**
- `n3_mac_tests` 新增：配额 2500 字节、5 段各 1000 字节 → 给下一段腾空间删 4 段、空日期目录也删；剩余空间下限不可能满足 → 删光就停，不死循环。fMP4 写 150 帧不 close（模拟 kill -9）→ 探测出 4167 ms；只有头的文件探测 ≤ 0；启动修复：补结束时间 1 条、删“读不出帧”的 1 条（连文件）、删“文件不在”的 1 条，再跑一次修 0 条。
- 配额：`m4 aaa.264 <根> 600 60 200 0`（不按实时速度）→ 10 个文件、回收删 7 段，最后剩 3 段 174413714 字节（166 MB）；`du -sm` 167 MB，索引 `sum(size_bytes)` 和 `stat` 加起来一致；没有 NULL。
- fMP4 结构（`mp4_box_walker` 顶层）：正常关闭 `ftyp moov (moof mdat)×N mfra`；kill -9 后没有 `mfra`。
- kill -9（`m4 … 600 10 200 1`，按实时速度，每段 10 秒）：
  - 加 `AVFMT_FLAG_FLUSH_PACKETS` 之前：25 秒时杀，最后一段应录约 117 帧，只救回 54 帧（上一个片段的尾巴还在 AVIO 缓冲区里）。
  - 加了之后：25 秒时杀，应录约 98 帧，救回 60 帧（只丢内存里还没写出的那个片段，≤ 60 帧，和计划一致）；33 秒时杀（刚开段），文件只有 `ftyp moov`，修复时连文件带记录删掉。
  - `m4repair` 后 `end_time_ms IS NULL` 为 0。
- 故障注入（给用户的题，“现象 → 定位 → 根因”在这里只记现象和根因，用户自己做定位）：
  1. **录像目录被删**（录到第 14 秒 `rm -rf ch0`）：程序不报错继续录。正在写的那段写进了已经被删的文件（fd 还开着，数据写进去了但目录里看不到），关段时 `file_size` 失败，索引里 `size_bytes = 0`；下一段重新建目录照常录。重启后 `m4repair` 把 2 条“文件不在”的记录删掉。根因：Linux 删文件只是删目录项，已打开的 fd 照样能写；程序没有检查“文件还在不在”。
  2. **数据库文件损坏**（4 KB 随机数据）：启动时 `建表失败：file is not a database`，程序退出，一帧都不录。根因：`sqlite3_open` 不检查内容，第一次执行 SQL 才发现。要不要改成“改名备份、重建空库、照常录”是产品决策，没改（推断 N5 要定）。
  3. **系统时间往回调**（没测：Mac 上改系统时间要 root）：推断现象是文件名和索引时间不变（段首时间 = 锚点 + 码流时间，锚点只在第一帧和断流后取），重启程序或断流重连后锚点用新的系统时间，新段时间比老段早，按时间查会重叠、回收按 `start_time_ms` 删会先删新段。上板用 `date -s` 测。
  4. **磁盘只读**：没测，推断 `avio_open` 失败 → 开新段失败 → 程序退出。

**和计划不一样的地方**
- fMP4 打开 `AVFMT_FLAG_FLUSH_PACKETS`（见上）。movflags 用 `frag_keyframe+empty_moov+default_base_moof`。
- `RecordIndex` 除了计划的 4 个函数，多了 `listAllRecordings()`（修“文件不存在”用）。
- `probeMp4DurationMs` 跳过 `AV_PKT_FLAG_CORRUPT` 的包（截断的最后一帧）。
- 回收：先删文件再删记录（反过来断电会留下没人管的文件）；日期目录删空了也删。下一段大小按上一段估。删的是所有通道里最早的段（N5 多路时，别的通道正在录的段如果最早，也可能被删到——N5 要处理，推断应该跳过 `end_time_ms IS NULL` 的段）。
- 启动修复里“读不出帧”的文件直接删（只有头的 fMP4、没有 moov 的普通 MP4）。
- `FfmpegFrameSource` 加 `setShouldPaceRawFile`：裸流按实时速度交帧（`m4` 默认开），代替计划里的“N1 实时发送”。
