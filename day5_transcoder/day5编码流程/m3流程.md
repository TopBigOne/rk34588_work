# M3 RTSP 播放
* 板子上跑 live555MediaServer，Mac 上用 VLC 看

> 本文没有 C++ 代码，只有一个运行脚本。2026-11-08 写的时候板子没连着，**整套流程还没实测**，标"推断"的地方第一次跑时要确认。

---

## 1. 干了什么

把 M1 / M2 转出来的 `out_720p.h265` 放在板子上，用一个现成的 RTSP 服务器（live555MediaServer）把它"发"出去，Mac 上用播放器通过网络地址 `rtsp://...` 来看。

M1、M2 是"文件进、文件出"。M3 第一次让码流**走网络**到另一台机器上播放。以后做网络摄像头（`cam_rtsp`），就是把这里的"文件"换成"摄像头实时编出来的码流"。

## 2. 输入和输出

| | 内容 |
|---|---|
| 输入 | 板子上 `/userdata/av/out_720p.h265`（M1 的输出）。同目录的 `out_720p_m2.h265`、`aaa.264` 也能播 |
| 输出 | 没有文件。Mac 上的播放器窗口里能看到画面 |

## 3. 技术点

### 3.1 RTSP 点播是什么

- **RTSP**（实时流协议）：播放器和服务器之间"说话"用的协议，管的是"我要看哪个、开始播、停"这些**控制命令**。
- **RTP**（实时传输协议）：真正装视频数据的包。一帧 H.265 切成好几个 RTP 包发出去，每个包带序号和时间戳。
- **点播**：服务器上存着文件，播放器连上来才从头开始发；和"直播"（摄像头一直在出画面）相对。

打个比方：RTSP 是你打电话给录像店"我要看第 3 号片子，现在开始放"；RTP 是录像店顺着管道送过来的一格一格画面。

播放器和服务器之间的对话大概是这样（每一条的细节在 [m4流程.md](m4流程.md) 里抓包看）：

| 命令 | 播放器问什么 | 服务器答什么 |
|---|---|---|
| OPTIONS | 你支持哪些命令？ | DESCRIBE、SETUP、PLAY…… |
| DESCRIBE | 这个文件是什么？ | 一段 SDP：H.265、RTP 负载类型号，以及 VPS/SPS/PPS |
| SETUP | 数据怎么传给我？ | 同意的传输方式，以及一个会话号 |
| PLAY | 开始播 | 好，然后开始发 RTP 包 |

### 3.2 live555MediaServer 怎么知道文件是 H.265

按**扩展名**。这个程序自带的帮助文字里写着（2026-11-08 在 Mac 上用 `strings` 看 A 盘里那份得到的）：

```
".264" => a H.264 Video Elementary Stream file
".265" => a H.265 Video Elementary Stream file
```

注意它认的是 **`.265`**。我们的输出叫 `out_720p.h265`，最后一个点后面是 `.h265`，推断 live555 认不出来。保险的做法是在板子上做一个 `.265` 结尾的链接，见 5.1 节。

它会把**自己启动时所在目录**里的文件当作点播源，URL 里的路径就是文件名：`rtsp://地址:端口/out_720p.265`。

### 3.3 为什么要"RTP over TCP"

按项目规定，Mac 和板子只走 USB（adb），不用板子 IP。办法是 `adb forward`：

```
Mac 上的播放器 → localhost:8554 ──USB──→ 板子上 live555 的端口
```

但 **`adb forward` 只能转 TCP**。RTP 默认走 UDP，服务器会往播放器的 IP 发 UDP 包，这条路在 USB 上是不通的。

解决：让播放器在 SETUP 时要求 **RTP over TCP**（也叫 interleaved）：视频数据和 RTSP 命令走**同一条 TCP 连接**，这条连接正好就是 adb 转发的那条。

- ffplay：加参数 `-rtsp_transport tcp`
- VLC：加参数 `--rtsp-tcp`，或者在偏好设置里勾选"RTP over RTSP (TCP)"

### 3.4 端口是 554 还是 8554

live555MediaServer 先试 554（RTSP 的标准端口），没有权限时改用 8554。**以它启动时打印的地址为准**（学习计划原文就是这么写的）。

板子上 adb shell 一般是 root，推断能拿到 554。脚本里板子端口默认填 554；启动日志如果打印的是 8554，就用 `BOARD_RTSP_PORT=8554 ./run_rtsp_server_via_usb.sh` 重新跑。Mac 这边一律用 8554：Mac 上普通用户不能监听 1024 以下的端口。

### 3.5 live555MediaServer 从哪来

两个来源，脚本里自动选：

1. **板子自带**：交叉编译工具链的 sysroot 里有 `usr/bin/live555MediaServer` 和它要的库（`libliveMedia.so.94` 等），推断板子的系统里也有
2. **A 盘里那份**：`~/Documents/AV/openedv/ATK-DLRK3588开发板网盘A盘_基础资料/01、程序源码/03、live555测试文件/live555MediaServer`。它是动态链接的（`readelf -d` 看到要 `libliveMedia.so.94`、`libgroupsock.so.30` 等），所以板子上也得有这些库

## 4. 脚本：`run_rtsp_server_via_usb.sh`

放在 `day5_transcoder/` 下，`chmod +x`。做 5 件事：确认板子连上 → 找 live555 → 停掉旧的 → `adb forward` → 启动 live555。

```sh
#!/bin/sh
# M3：在板子上启动 live555MediaServer（RTSP 点播服务器），并用 adb forward 把它的端口转到 Mac。
# 全程走 USB（adb），不用板子 IP。
#
# 用法：./run_rtsp_server_via_usb.sh
# 然后在 Mac 上播放：ffplay -rtsp_transport tcp rtsp://localhost:8554/out_720p.h265
#
# 可选环境变量：
#   ADB_SERIAL=xxxx        同时连了多台 adb 设备时，指定板子的序列号
#   BOARD_RTSP_PORT=8554   live555 启动时打印的端口不是 554 时，按打印的改
#
# 停止：Ctrl+C 只能停掉 Mac 这边的 adb，板子上的 live555 可能还在跑。
#      下次运行本脚本时会先把旧的停掉；也可以手动 adb shell "killall live555MediaServer"

MEDIA_DIR=/userdata/av            # live555 把"当前目录"里的文件当点播源，转码结果就在这里
LOCAL_RTSP_PORT=8554              # Mac 这边的端口：VLC / ffplay 连 localhost:8554
BOARD_RTSP_PORT=${BOARD_RTSP_PORT:-554}  # 板子上 live555 监听的端口：默认先试 554（推断，以启动日志为准）
# A 盘里正点原子给的 live555MediaServer：板子上没有自带的时候才用它
LIVE555_LOCAL="$HOME/Documents/AV/openedv/ATK-DLRK3588开发板网盘A盘_基础资料/01、程序源码/03、live555测试文件/live555MediaServer"

ADB=adb
if [ -n "$ADB_SERIAL" ]; then
    ADB="adb -s $ADB_SERIAL"
fi

# 第 1 步 确认板子连上了
if ! $ADB get-state >/dev/null 2>&1; then
    echo "adb 没找到板子：检查板子开机了吗、OTG 线（TypeC0 口）插好了吗，执行 adb devices 看看" >&2
    exit 1
fi

# 第 2 步 找 live555MediaServer：板子自带的优先（Buildroot 的 sysroot 里有，推断板子 /usr/bin 下也有），没有就从 A 盘传一个
if $ADB shell "command -v live555MediaServer" < /dev/null >/dev/null 2>&1; then
    LIVE555_BIN=live555MediaServer
    echo "用板子自带的 live555MediaServer"
else
    $ADB push "$LIVE555_LOCAL" "$MEDIA_DIR/" >/dev/null || exit 1
    $ADB shell "chmod +x $MEDIA_DIR/live555MediaServer" < /dev/null || exit 1
    LIVE555_BIN=./live555MediaServer
    echo "板子上没有自带的，用 A 盘里的 live555MediaServer"
fi

# 第 3 步 把上次没停掉的 live555 停掉，否则端口被占着，新的起不来
$ADB shell "killall live555MediaServer" < /dev/null >/dev/null 2>&1

# 第 4 步 端口转发：Mac 的 localhost:8554 ←USB→ 板子的 BOARD_RTSP_PORT
# adb forward 只转 TCP，所以播放器要用"RTP over TCP"（RTSP 和视频数据走同一条 TCP 连接）
$ADB forward tcp:$LOCAL_RTSP_PORT tcp:$BOARD_RTSP_PORT || exit 1
echo "端口转发：Mac localhost:$LOCAL_RTSP_PORT → 板子 $BOARD_RTSP_PORT"

# 第 5 步 在 MEDIA_DIR 里启动 live555（前台运行，日志直接显示在这个终端）
echo "=== 板子上启动 $LIVE555_BIN（目录 $MEDIA_DIR）==="
echo "    启动日志里的 rtsp://<板子IP>:<端口>/ 只看端口；Mac 上一律连 rtsp://localhost:$LOCAL_RTSP_PORT/文件名"
exec $ADB shell "cd $MEDIA_DIR && $LIVE555_BIN" < /dev/null
```

## 5. 运行步骤

### 5.1 准备（只做一次）

```bash
# 确认转码结果在板子上
adb shell ls -l /userdata/av/out_720p.h265

# 做一个 .265 结尾的链接，让 live555 按扩展名认出 H.265（见 3.2 节）
adb shell "cd /userdata/av && ln -sf out_720p.h265 out_720p.265"
```

### 5.2 终端 1：启动服务器

```bash
cd day5_transcoder
./run_rtsp_server_via_usb.sh
```

看启动日志里的地址，确认端口是 554 还是 8554（见 3.4 节）。这个终端一直开着。

### 5.3 终端 2：Mac 上播放

```bash
# ffplay（命令行，出问题时日志更清楚，建议先用它）
ffplay -rtsp_transport tcp rtsp://localhost:8554/out_720p.265

# VLC
/Applications/VLC.app/Contents/MacOS/VLC --rtsp-tcp rtsp://localhost:8554/out_720p.265
```

### 5.4 停止

关掉播放器；终端 1 按 Ctrl+C；再执行一次 `adb shell "killall live555MediaServer"`，确认板子上的也停了。

## 7. 可能遇到的问题

| 现象 | 可能的原因 | 怎么办 |
|---|---|---|
| live555 启动就报找不到 `libliveMedia.so.94` | 板子上没有 live555 的库 | 先 `adb shell ls /usr/lib/ \| grep -i live` 看看；没有的话从工具链 sysroot 的 `usr/lib` 里 push 这 4 个库 |
| 播放器连不上（Connection refused） | `adb forward` 的板子端口和 live555 实际监听的端口不一致 | 按启动日志设 `BOARD_RTSP_PORT` 重跑 |
| 连上了但一直没画面、或者超时 | 播放器在用 UDP 收 RTP | 确认加了 `-rtsp_transport tcp` / `--rtsp-tcp` |
| 404 / Stream Not Found | 文件名不对，或扩展名 live555 不认识 | 用 `.265` 结尾的链接（5.1 节） |
| 播放速度明显不对 | live555 从码流里读帧率，读不到就用默认值（推断） | 先记下现象，不在 M3 深究 |
