## 1. 要做什么

在 RK3588 板子的屏幕上播放一个 mp4 文件，有画面也有声音，可以暂停、拖进度条。

| 项目 | 选择 | 原因 |
|---|---|---|
| 视频解码 | **MPP 硬解**（H.264 / H.265） | 主线 |
| 拆封装 | ffmpeg 的 libavformat（只拆封装，不解码） | 板子的 ffmpeg 4.4.1 没有 rkmpp，但拆封装用不到解码器 |
| 码流格式转换 | ffmpeg 的 bitstream filter `h264_mp4toannexb` / `hevc_mp4toannexb` | mp4 里存的是 AVCC（长度头），MPP 要 Annex B（起始码） |
| 颜色转换和缩放 | **RGA**：NV12 → RGBX，同时缩放到窗口大小 | 不用 CPU 做这两件最费时的事 |
| 显示 | Qt 5.15.8 Widgets，`paintEvent` 里画 `QImage` | 板子自带 Qt 5.15.8，开发环境 day7_qt_env 已搭好 |
| 音频解码 | ffmpeg 的 aac 解码器（软解） | RK3588 没有音频解码硬件，MPP 只管视频；AAC 软解只占很少的 CPU |
| 音频格式转换 | libswresample：float planar → S16 交错 | ALSA 一般只收交错的整数采样 |
| 音频输出 | **ALSA**（`snd_pcm_writei`） | Linux 上最底层的声卡接口，相当于 Android 的 AAudio |
| 音视频同步 | **以音频时钟为准** | 人耳对声音卡顿比眼睛对掉帧敏感，所以让声音匀速播，画面去追声音 |

板子上已经确认有：ffmpeg 4.4.1（`mov,mp4` 拆封装器、`h264_mp4toannexb`、`hevc_mp4toannexb`），Qt 5.15.8（Widgets、wayland 插件），sysroot 里有 libavformat / libavcodec / libswresample / libasound 的头文件和 `.pc` 文件。

**还没确认**（板子插上后第一件事）：板子 ffmpeg 有没有 `aac` 解码器、`aplay -l` 有几张声卡、喇叭或耳机插哪里。

## 2. 数据流

```
                      ┌─────────────── 解封装线程 ───────────────┐
 movie.mp4 ──────────▶│ av_read_frame → 按 stream_index 分到两个队列 │
                      └──────────┬─────────────────────┬───────────┘
                                 │视频包（AVCC）          │音频包（AAC）
                                 ▼                       ▼
                       [视频包队列，容量 64]       [音频包队列，容量 64]
                                 │                       │
         ┌───────────── 视频线程 ┴──────────┐   ┌──── 音频线程 ┴──────────────┐
         │ mp4toannexb → MPP 硬解 → NV12     │   │ aac 软解 → float planar PCM  │
         │ → RGA 转 RGBX 并缩放到窗口大小     │   │ → swresample → S16 交错 PCM   │
         │ → 等到"音频时钟 ≥ 这帧的 pts"     │   │ → snd_pcm_writei（写满就阻塞）│
         │ → 发信号把 QImage 交给 UI 线程    │   │ → 更新音频时钟                │
         └─────────────┬────────────────────┘   └─────────────┬────────────────┘
                       │ Qt 信号（跨线程，排队连接）               │
                       ▼                                       ▼
              UI 线程：VideoWidget::paintEvent 画出来        声卡 → 喇叭 / 耳机
```

一共 4 个线程：

| 线程 | 干什么 | 在哪里等 |
|---|---|---|
| UI 线程（主线程） | Qt 事件循环：按钮、进度条、重画画面 | 没事时睡在事件循环里 |
| 解封装线程 | 读 mp4，把包分给两个队列 | 队列满了就等（背压） |
| 视频线程 | 解码、转格式、按时间把画面交给 UI | 包队列空了等；画面早了等音频时钟追上来 |
| 音频线程 | 解码、写声卡 | 包队列空了等；声卡缓冲区满了 `snd_pcm_writei` 阻塞 |

**节奏由声卡定**：声卡按 48000 采样/秒匀速消耗数据，写满了 `snd_pcm_writei` 就阻塞，所以音频线程自己就是匀速的。视频线程看音频时钟，画面早了就等，晚太多（超过 100 ms）就丢掉这帧，不显示。


## 4. 每个类管什么、谁拥有谁

| 类 | 管什么 | 谁拥有它 | 什么时候释放 |
|---|---|---|---|
| `PlayerWindow` | 窗口、按钮、进度条 | `main()` 里的局部变量 | 程序退出 |
| `VideoWidget` | 保存最新一帧 `QImage`，`paintEvent` 画出来 | `PlayerWindow`（Qt 父子关系） | 窗口销毁时 |
| `PlayerController` | 打开文件、建线程、处理暂停和 seek | `PlayerWindow` | 窗口销毁时，先停所有线程 |
| `Mp4Demuxer` | `AVFormatContext` | `PlayerController` | 关闭文件或析构 |
| `PacketQueue` ×2 | 排队的 `AVPacket` | `PlayerController` | 析构时释放剩下的包 |
| `AnnexbConverter`、`MppVideoDecoder`（RGA 转换是一个函数 `convertNv12FrameToRgbxByRga`） | 视频的处理 | `VideoWorker` | 线程结束 |
| `SoftwareAudioDecoder`、`AudioResampler`、`AlsaAudioOutput` | 音频的三步处理 | `AudioWorker` | 线程结束 |
| `MediaClock` | 当前播放到哪里（微秒） | `PlayerController`，两个线程都拿它的引用 | 析构 |

所有 C 库的对象（`AVFormatContext`、`AVPacket`、`AVFrame`、`MppFrame`、`snd_pcm_t`……）都包进 `unique_ptr` 加删除器，变量名以 `Ptr` 结尾，和以前一样。

## 5. 几个关键设计

### 5.1 时间统一用微秒

mp4 里每个流有自己的时间单位（`time_base`，比如视频 1/15360 秒、音频 1/48000 秒）。包一读出来就换算成微秒（`av_rescale_q(pts, stream->time_base, {1, 1000000})`），后面所有模块只认微秒，变量名带 `Us` 结尾（`ptsUs`、`positionUs`）。

送进 MPP 时用 `mpp_packet_set_pts` 带上 pts，解出来的帧用 `mpp_frame_get_pts` 取回。MPP 只是原样搬运这个数，不关心单位。

### 5.2 一个包就是一帧，不用内部分帧

Day 2～6 是从裸 `.h264` 文件按 64 KB 一块读，要打开 `split_parse` 让 MPP 自己找帧边界。mp4 拆出来的每个包本来就是完整的一帧，所以**关掉 split_parse**，一个包送一次。

### 5.3 音频时钟

```
音频时钟（现在喇叭里正在响的是哪个时刻的声音）
  = 最后写进声卡的那个采样的 pts  −  声卡里还没播出去的采样数 ÷ 采样率
```

"还没播出去的采样数"用 `snd_pcm_delay` 查。音频线程每写一次就更新一次，视频线程随时读（用 `std::atomic` 或加锁，不会读到半个数）。

没有音轨的 mp4：退回用系统时钟（`std::chrono::steady_clock`）。

### 5.4 画面直接缩放到窗口大小

屏幕是竖屏 1080×1920，1080p 横屏视频要缩小到 1080×608 左右才放得下。如果把 1920×1080 的 `QImage` 交给 Qt，让 `QPainter` 缩放，每一帧都是 CPU 在算。所以视频线程从 `VideoWidget` 拿到"现在要显示多大"，**RGA 一步做完颜色转换加缩放**，Qt 只负责原样贴上去。

RGBX 格式（第 4 个字节不用）对应 `QImage::Format_RGBX8888`，画的时候不用算透明度混合。

### 5.5 seek（拖进度条）

拖进度条最容易出问题：队列里还有旧位置的包，解码器里还有旧的参考帧，声卡里还有旧的声音。做法是给每个包带一个"第几次 seek"的编号（serial）：

1. UI 发起 seek → 解封装线程调用 `av_seek_frame`（跳到目标位置前面最近的关键帧），serial 加 1，清空两个包队列
2. 视频线程拿到 serial 变了的包：调用 MPP 的 `reset` 清掉解码器里的旧帧，丢掉 pts 比目标时间早的画面
3. 音频线程拿到 serial 变了的包：`avcodec_flush_buffers` 清解码器，`snd_pcm_drop` 扔掉声卡里没播的旧声音，重设音频时钟

### 5.6 暂停

- 音频线程停止写数据，调用 `snd_pcm_pause`（声卡不支持时用 `snd_pcm_drop`，恢复时重新 `snd_pcm_prepare`）
- 音频时钟停住，视频线程在"等时钟追上来"那一步自然就停了
- 解封装线程不用管，队列满了它自己会停

## 7. 新知识点的够用线

| 知识点 | 够用线 | 先不学 |
|---|---|---|
| Qt | `QWidget` 窗口和布局，`paintEvent` 画 `QImage`，信号和槽（跨线程时自动排队），CMake 交叉编译 Qt 程序 | QML、Qt Multimedia、Qt 的事件循环内部 |
| libavformat | `avformat_open_input` → `avformat_find_stream_info` → `av_read_frame` 循环 → `av_seek_frame`；`time_base` 和 pts 怎么换算 | 各种容器格式的内部结构 |
| bitstream filter | 知道 AVCC 和 Annex B 的区别，会用 `av_bsf_send_packet` / `av_bsf_receive_packet` | filter 的内部实现 |
| libavcodec（音频） | `avcodec_send_packet` / `avcodec_receive_frame` 循环；`AVFrame` 里 planar 和交错的区别 | AAC 编码原理 |
| ALSA | `snd_pcm_open` → 设置格式、采样率、声道、缓冲区大小 → `snd_pcm_writei` 循环；`snd_pcm_delay`；遇到 underrun（-EPIPE）用 `snd_pcm_prepare` 恢复 | ALSA 插件、dmix、asoundrc 配置、驱动 |
| 音视频同步 | 以音频时钟为准，视频早了等、晚了丢 | 以视频为主时钟、外部时钟、变速播放 |
