## 1. 现在的状况：板子上没有检测到摄像头（2026-10-15 实测）

| 检查 | 结果 | 说明 |
|---|---|---|
| `dmesg \| grep imx415` | `imx415 3-001a: Unexpected sensor id(000000), ret(-5)`<br>`imx415 7-001a: Unexpected sensor id(000000), ret(-5)` | 设备树里配了两个 IMX415（I2C 总线 3 和 7，地址都是 0x1a）。驱动开机时通过 I2C 读芯片 ID，`ret(-5)` 是 `-EIO`：**那个地址上没有芯片应答** |
| `media-ctl -p` | 所有 `/dev/media*` 里都**没有 imx415 实体** | 正常的链路是 sensor → CSI → ISP，现在最前面那一环缺了 |
| `pidof rkaiq_3A_server` | 没有输出 | 开机时 `/etc/init.d/S40rkaiq_3A` 启动过它，因为每个 media 设备都报 `Bad media topology`（找不到 sensor），它自己退出了 |

> ⚠️ **`/dev/video31` 存在 ≠ 摄像头存在**。`video31` 是 ISP 驱动创建的节点，不接摄像头它也在。`v4l2-ctl --list-devices` 能看到 `rkisp_mainpath` 也说明不了什么。判断摄像头在不在，看的是下面第 2 节的 3 条检查。

## 2. 装摄像头，然后跑 3 条检查

### 2.1 安装
1. **断电**（拔掉电源，不只是关机）。带电插拔排线可能烧坏摄像头或者板子
2. 排线插到板子的 MIPI CSI 摄像头接口，**注意金手指朝向**，卡扣压紧
3. 板子有两个摄像头接口，设备树里两个都配了（就是上面的 I2C 3 和 7），插哪个都行，但**不同接口对应的 video 节点不一样**（见 2.3）
4. 上电开机

### 2.2 3 条检查（三条都对才算装好）

```bash
# ① 驱动读到芯片了：不应该再有 "Unexpected sensor id"
adb shell 'dmesg | grep imx415 | grep -i unexpected'          # 期望：什么都不输出（只剩没插的那个接口会报）

# ② 链路里有 sensor 了：能看到 imx415 实体
adb shell 'for m in /dev/media*; do media-ctl -d $m -p 2>/dev/null | grep -q imx415 && echo $m; done'   # 期望：打印出一个 /dev/mediaX

# ③ 3A 服务在运行：能打印出 pid
adb shell 'pidof rkaiq_3A_server'
```

> 注意第 ① 条：两个接口只插了一个的话，**没插的那个照样会报 `Unexpected sensor id`**。所以准确的判断是"插的那个接口不再报"，并且第 ② 条能找到 imx415。

### 2.3 找到要用的 video 节点

板子上有两个 ISP 实例，各自有一个 `rkisp_mainpath` 节点（2026-10-15 实测）：

| ISP | `v4l2-ctl --list-devices` 里的名字 | mainpath 节点 |
|---|---|---|
| ISP 0 | `rkisp_mainpath (platform:rkisp0-vir0)` | `/dev/video22` |
| ISP 1 | `rkisp_mainpath (platform:rkisp1-vir0)` | `/dev/video31` |

摄像头插在哪个接口，就接到哪个 ISP 上。总计划里写的是 `video31`，但**以实际为准**：用第 ② 条找到的 `/dev/mediaX`，看它里面的 `rkisp_mainpath` 是哪个节点：

```bash
adb shell 'media-ctl -d /dev/mediaX -p | grep -A2 "rkisp_mainpath"'   # 把 X 换成第 ② 条打印的数字，看 "device node name /dev/videoNN"
```

后面的命令都按 **2026-10-17 实测的 `/dev/video22`**（摄像头装在 MIPI CSI3 → ISP0）写；装在别的接口上，换成你查到的节点。设备节点编号是开机时按顺序分配的，更新系统、换接口后可能会变，**每次开始前都查一遍**。

### 2.4 3A 服务没起来怎么办

3A（自动曝光 AE、自动白平衡 AWB、自动对焦 AF）由 `rkaiq_3A_server` 负责。它不运行，ISP 就不调曝光和白平衡，画面会很暗、发绿或者发紫。

```bash
adb shell 'grep rkaiq_3A /var/log/messages | tail -20'   # 看它为什么退出（没摄像头时是 "Bad media topology"）
adb shell '/etc/init.d/S40rkaiq_3A start'                 # 摄像头装好以后，手动再启动一次
adb shell 'pidof rkaiq_3A_server'
```

> 正常情况下装好摄像头重新开机，它会自己启动，不用手动起。

## 3. M0：先用官方 `mpi_enc_test` 录一段（不写代码）

板子上已经有编好的官方测试程序 `/userdata/mpp_build/bin/mpi_enc_test`。它支持直接把 `/dev/videoN` 当输入（源码 `mpi_enc_test.c` 第 188～190 行：输入路径以 `/dev/video` 开头就调用 `camera_source_init`）。

```bash
adb shell 'LD_LIBRARY_PATH=/userdata/mpp_build/lib /userdata/mpp_build/bin/mpi_enc_test \
    -i /dev/video22 -w 1920 -h 1080 -t 7 -n 300 -o /userdata/av/cam_official.h264'
./run_move_file_from_board_via_usb.sh /userdata/av/cam_official.h264
ffplay result_from_board/cam_official.h264
```

- `-t 7` 是 H.264（`MPP_VIDEO_CodingAVC = 7`），不给 `-f` 就是 NV12
- 它自己会先跳过 50 帧（第 629 行 `cap_num++ < 50`），所以录出来的是第 51 帧以后的画面
- **这一段能正常播放，说明摄像头、ISP、3A、编码器这条链路全是通的**。后面自己的程序出问题时，拿它来对比

## 4. M1：用 `v4l2-ctl` 抓一帧 NV12（不写代码）

```bash
# 设格式 → 用 4 块 MMAP 缓冲区 → 跳过前 30 帧 → 存 1 帧
adb shell 'v4l2-ctl -d /dev/video22 --set-fmt-video=width=1920,height=1080,pixelformat=NV12 \
    --stream-mmap=4 --stream-skip=30 --stream-count=1 --stream-to=/userdata/av/cam_1frame.nv12'
./run_move_file_from_board_via_usb.sh /userdata/av/cam_1frame.nv12
ffplay -f rawvideo -pixel_format nv12 -video_size 1920x1080 result_from_board/cam_1frame.nv12
```

**抓之前先看格式**：不用接摄像头也能问驱动"1920×1080 的 NV12，你会怎么排布"（`--try-fmt-video` 只是试探，不改设置）。2026-10-15 板子实测：

```bash
adb shell 'v4l2-ctl -d /dev/video22 --try-fmt-video=width=1920,height=1080,pixelformat=NV12'
```

| 请求 | 节点类型 | `Bytes per Line` | `Size Image` | 说明 |
|---|---|---:|---:|---|
| 1920×1080 NV12 | Video Capture **Multiplanar**，1 个 plane | 1920 | 3,110,400 | = 1920 × 1080 × 3/2，**UV 紧跟在第 1080 行后面，没有补到 1088** |
| 1280×720 NV12 | 同上 | 1280 | 1,382,400 | = 1280 × 720 × 3/2 |

所以抓下来的文件应该正好 3,110,400 字节，`-video_size 1920x1080` 就能正确播放。装好摄像头以后，用 `v4l2-ctl -d /dev/video22 --get-fmt-video` 再确认一次实际值（未实测）。

> 这个"UV 从第 1080 行开始"非常重要，Day 1 的编码器默认按 1088 行算，直接复用会花屏，见 [03_写代码_M1到M6.md](03_写代码_M1到M6.md) 第 3 节。

另外 `--list-formats` 能看到 mainpath 支持的格式（实测）：`UYVY`、`NV16`、`NV61`、`NV21`、`NV12`、`NM21`、`NM12`。我们用 `NV12`。

## 5. CLion 和脚本

### 5.1 CMake profile
和 Day 1 一样，要加一个交叉编译的 profile：Settings → Build, Execution, Deployment → CMake → **+**

| 项 | 值 |
|---|---|
| Name | `RK3588-Debug` |
| CMake options | `-DCMAKE_TOOLCHAIN_FILE=/Users/dev/rk-toolchain/rk3588-toolchain.cmake` |
| Build directory | `cmake-build-rk3588-debug`（脚本按这个目录找程序） |

### 5.2 脚本（都走 USB/adb，不用板子 IP）

| 脚本 | 作用 |
|---|---|
| `run_on_board_with_mac.sh [参数...]` | 编译 → `adb push` 到 `/tmp/CLion/run` → 在板子上运行 |
| `run_debug_on_board_via_usb.sh [参数...]` | 编译 → 推到板子 → `gdbserver :1234`；然后在 CLion 里启动 Remote Debug（`localhost:1234`，GDB profile 选 RK3588-GDB） |
| `run_move_file_from_board_via_usb.sh [板子上的文件]` | 把文件拉回 `result_from_board/`，核对大小后删掉板子上那份（`KEEP=1` 只拷贝不删）。默认拉 `/userdata/av/out.h264` |

### 5.3 磁盘空间
`/userdata` 还有 98G（2026-10-15 实测）。1080p NV12 每帧 3MB，存原始帧的时候别存太多；`.h264` 10 秒只有几 MB。
