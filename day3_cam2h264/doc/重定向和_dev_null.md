# 重定向和 /dev/null：`>/dev/null 2>&1` 是什么意思

> 脚本里常见 `$ADB start-server >/dev/null 2>&1`、`$ADB shell "..." < /dev/null` 这种写法。
> **一句话**：`>/dev/null 2>&1` = 这条命令输出的所有东西（正常的 + 错误的）都扔掉，不显示。
> 本文的输出都是 2026-10-18 在 Mac 和板子上实测的。

---

## 1. 每个程序天生有 3 个"口"

| 编号 | 名字 | 方向 | 默认连到 | C 里谁用它 |
|:---:|---|---|---|---|
| **0** | stdin（标准输入） | 进 | 键盘 / 终端 | `scanf`、`fgets(stdin)` |
| **1** | stdout（标准输出） | 出：正常信息 | 屏幕 | `printf`、`puts`、我们的 `LOGx` |
| **2** | stderr（标准错误） | 出：错误信息 | 屏幕 | `perror`、`fprintf(stderr, ...)` |

正常信息和错误信息平时都显示在屏幕上，看起来一样，其实是**两个不同的口**，可以分开处理。

> 这 3 个编号就是文件描述符（fd）0、1、2。程序启动时它们已经打开好了，所以我们 `open("/dev/video22")` 拿到的 fd 从 3 开始往后排。

---

## 2. 重定向：把某个口改接到别处

| 写法 | 意思 |
|---|---|
| `命令 > 文件` | **1 号口**改为写进文件（`>` 前面省略的数字就是 1，等于 `1> 文件`）；文件原来的内容会被清掉 |
| `命令 >> 文件` | 同上，但是**追加**到文件末尾 |
| `命令 2> 文件` | **2 号口**改为写进文件 |
| `命令 2>&1` | 2 号口**接到 1 号口现在接的地方**（`&1` = "1 号口"，不是叫 1 的文件） |
| `命令 < 文件` | **0 号口**改为从文件读 |

**记法：箭头朝哪边，数据就往哪边流。** `>` 是从命令流到文件（输出），`<` 是从文件流进命令（输入）。

---

## 3. `/dev/null`：黑洞

- **写进去的东西直接消失**，写多少都行
- **读它，马上读到"结束"**，一个字节都没有

```bash
echo hello > /dev/null        # 什么都没有，hello 被扔了
wc -c < /dev/null             # 实测：0 字节
```

它是一个设备文件，由内核提供（实测）：
```
板子：crw-rw-rw- 1 root root 1, 3 /dev/null      ← c = 字符设备，主设备号 1，次设备号 3
Mac ：crw-rw-rw- 1 root wheel ... /dev/null
```
和 `/dev/video22` 是同一类东西（见 [FindCamera输出的每个字段是什么.md](FindCamera输出的每个字段是什么.md)、guide/04 第 2 节），只是它背后的"设备"什么都不做。

## 4. 实测：几种写法的效果

用一个小脚本 `demo.sh` 实测，它往 1 号口、2 号口各输出一行：
```sh
#!/bin/sh
echo "我是正常输出（stdout，1 号）"
echo "我是错误输出（stderr，2 号）" >&2       # >&2 = 这一行写到 2 号口
```

| 写法 | 屏幕上看到的（实测） |
|---|---|
| `./demo.sh` | 两行都有 |
| `./demo.sh > /dev/null` | 只剩 `我是错误输出…` |
| `./demo.sh 2> /dev/null` | 只剩 `我是正常输出…` |
| **`./demo.sh > /dev/null 2>&1`** | **什么都没有** |
| `./demo.sh 2>&1 > /dev/null` ⚠️ | **还剩 `我是错误输出…`**（顺序写反了，见第 5 节） |
| `./demo.sh > out.txt 2> err.txt` | 屏幕上没有；`out.txt` 里是正常那行，`err.txt` 里是错误那行 |

---

## 5. ⚠️ 坑：`2>&1` 要写在后面

重定向**从左往右**一个一个执行：

```
./demo.sh  > /dev/null  2>&1
           ① 1 号 → 黑洞   ② 2 号 → "1 号现在接的地方" = 黑洞      ✅ 都扔了

./demo.sh  2>&1  > /dev/null
           ① 2 号 → "1 号现在接的地方" = 屏幕   ② 1 号 → 黑洞     ❌ 2 号还在屏幕上
```

`2>&1` 是"复制 1 号口**此刻**的接法"，不是"以后永远跟着 1 号口"。所以**先改 1 号口，再写 `2>&1`**。

---

## 6. 我们脚本里的这些写法

| 写法 | 出现在 | 意思 |
|---|---|---|
| `$ADB start-server >/dev/null 2>&1` | 所有 adb 脚本 | 启动 adb 服务时会打印 `* daemon started successfully` 之类的，不想看 → 全扔 |
| `$ADB get-state >/dev/null 2>&1` | 所有 adb 脚本 | 只关心命令**成功没有**（退出码），不关心它打印了什么 |
| `$ADB push ... >/dev/null` | `run_on_board_with_mac.sh` | 扔掉 push 的进度信息；但**错误还会显示**（只扔了 1 号口） |
| `stat -c %s '$SRC' 2>/dev/null` | 拉文件脚本（在板子上执行） | 文件不存在时 stat 会报错，只扔掉报错，结果为空字符串，脚本据此判断"找不到" |
| `$ADB shell "..." < /dev/null` | 所有 adb 脚本 | **给一个空输入**，adb 就不会去读终端里粘贴的下一行（见 [adb_shell会吃掉终端输入.md](adb_shell会吃掉终端输入.md)） |
| `命令 \|\| exit 1` | 所有脚本 | 前面的命令失败（退出码不是 0）就退出脚本 |

> **扔掉输出 ≠ 不知道成功没有**：`> /dev/null 2>&1` 只是不显示，命令的**退出码**照样在。实测：`ls /etc/hosts /nope > /dev/null 2>&1; echo $?` 屏幕上什么都没有，但打印 `1`（有个文件不存在，ls 失败了）。所以脚本里可以放心地 `$ADB get-state >/dev/null 2>&1 || 报错退出`。
