# 终端彩色输出：ANSI 颜色码

> 让程序的输出像 Android Studio 的 logcat 一样，不同级别不同颜色。day3 已经写好了一个小工具 `src/common/log.h`（`LOGV / LOGD / LOGI / LOGW / LOGE`），`FindCamera` 已经在用。
> 本文的输出都是 2026-10-17 在板子上实测的（通过 `run_on_board_with_mac.sh` 运行，CLion 终端显示）。

---

## 1. 原理：一串"看不见"的字符

终端（CLion 的 Terminal、Run 窗口，macOS 的终端……）有一个约定：**看到 `ESC [ 数字 m` 这种字符串，不把它显示出来，而是用它切换后面文字的颜色**。

- `ESC` 是一个不可见字符，ASCII 码 27，C 语言里写成 `\033`（八进制）或 `\x1b`
- 这套约定叫 **ANSI 转义码**（ANSI escape code），几乎所有终端都支持

```cpp
printf("\033[31m" "这几个字是红色" "\033[0m" "这几个字恢复默认颜色\n");
//       ↑ 开始红色                   ↑ 恢复默认（0 = reset）
```

常用的颜色码：

| 码 | 颜色 | 码 | 颜色 |
|---|---|---|---|
| `\033[30m` | 黑 | `\033[90m` | 灰（亮黑） |
| `\033[31m` | 红 | `\033[91m` | 亮红 |
| `\033[32m` | 绿 | `\033[92m` | 亮绿 |
| `\033[33m` | 黄 | `\033[93m` | 亮黄 |
| `\033[34m` | 蓝 | `\033[94m` | 亮蓝（深色背景上比 34 好看） |
| `\033[35m` | 紫 | `\033[36m` | 青 |
| `\033[1m` | **加粗** | `\033[0m` | ⭐ **恢复默认**（每次用完颜色都要加） |

可以组合，比如 `\033[1;31m` = 加粗 + 红色。

### 1.1 实测：这些字符真的在输出里

终端会把颜色码"吃掉"，看不到。用 `cat -v` 能把不可见字符显示出来（`^[` 就是 ESC）：

```bash
adb shell /tmp/CLion/run/day3_cam2h264 | cat -v
```
```
^[[94m17:32:46.448 D FindCamera: /dev/media0  model=rkcif-mipi-lvds    13 个实体^[[0m
^[[32m17:32:46.448 I FindCamera:   main path  : /dev/video22   ← 录像用这个^[[0m
↑ 蓝色开始                                                              ↑ 恢复默认
```

### 1.2 为什么通过 adb 运行也有颜色

程序在**板子上**运行，把这些字符原样写到 stdout → adb 原样传回 Mac → **Mac 上的 CLion 终端**看到颜色码，显示成颜色。板子本身不需要"支持颜色"，颜色是在显示的那一端变出来的。

## 2. day3 的日志工具：`src/common/log.h`

### 2.1 用法

```cpp
#include "common/log.h"

LOGD("FindCamera", "%s model=%s", path.c_str(), model.c_str());   // 橙色：调试细节
LOGI("FindCamera", "main path : %s", mainPath.c_str());           // 绿色：重要结果
LOGW("Camera", "丢帧：sequence 从 %u 跳到 %u", last, cur);          // 黄色：警告（例子）
LOGE("Camera", "open %s failed: %s", dev, strerror(errno));         // 红色：错误（例子）
```

- 第一个参数是**标签（tag）**，一般写模块或者类名，和 Android 的 `Log.d(TAG, ...)` 一样
- 后面和 `printf` 一样写，**末尾不用写 `\n`**，每条自动换行

输出格式（照 logcat）：
```
17:32:46.449 I FindCamera:   main path  : /dev/video22
└─ 时间 ─────┘ └ 级别 └ 标签 ┘└ 内容 ─────────────────────┘
```

| 宏 | 级别 | 颜色（RGB） | 颜色码 | 对应 Android |
|---|---|---|---|---|
| `LOGV` | Verbose | 蓝 `0E83E3` | `\033[38;2;14;131;227m` | `Log.v` |
| `LOGD` | Debug | 橙 `DA7537` | `\033[38;2;218;117;55m` | `Log.d` |
| `LOGI` | Info | 绿 `108A0D` | `\033[38;2;16;138;13m` | `Log.i` |
| `LOGW` | Warn | 黄 `E8A908` | `\033[38;2;232;169;8m` | `Log.w` |
| `LOGE` | Error | 红 `C40E0A` | `\033[38;2;196;14;10m` | `Log.e` |

### 2.1.1 指定任意 RGB 颜色：24 位真彩色

第 1 节那张表里的 `\033[31m` 这些只有 16 种固定颜色，具体是什么红、什么绿由终端主题决定。想要精确的颜色（比如照 logcat 的配色），用 **24 位真彩色**写法：

```
\033[38;2;R;G;Bm        38 = 设置文字颜色（48 = 背景色），2 = 后面跟 R;G;B，三个都是十进制 0～255
```

从十六进制颜色换算：`DA7537` → R=0xDA=218，G=0x75=117，B=0x37=55 → `\033[38;2;218;117;55m`。
如果颜色写成 `RRGGBBAA`（比如 `DA7537FF`），最后两位是不透明度，终端用不到，去掉就行。

实测（2026-10-17，`cat -v` 看原始输出）：
```
^[[38;2;218;117;55m18:08:30.840 D FindCamera: /dev/media0  model=rkcif-mipi-lvds ...^[[0m
^[[38;2;16;138;13m18:08:30.841 I FindCamera: 找到 1 个摄像头：^[[0m
```
CLion 的终端支持真彩色；很老的终端不支持时，可能显示成相近的颜色或者没有颜色。

### 2.2 关掉颜色：`NO_COLOR`

把输出存到文件时，文件里会出现 `^[[32m` 这些乱码。设置环境变量 `NO_COLOR` 就不输出颜色（实测）：

```bash
adb shell 'NO_COLOR=1 /tmp/CLion/run/day3_cam2h264 > /userdata/av/log.txt'
```

`NO_COLOR` 是很多命令行工具通用的约定（no-color.org）。

### 2.3 实现里的几个细节

| 写法 | 为什么 |
|---|---|
| `__attribute__((format(printf, 3, 4)))` | 让编译器像检查 `printf` 一样检查格式串和参数，比如 `%s` 传了 `int` 会报警告 |
| 每条日志后 `fflush(stdout)` | 通过 adb 运行时，板子上的 stdout 不是终端，是**全缓冲**的：不刷新的话日志会攒一大段才出来，程序崩溃时最后几条还会丢 |
| 没用 `isatty()` 判断"是不是终端" | 很多工具用 `isatty(STDOUT_FILENO)` 判断：输出到终端才加颜色。但通过 adb 运行时，板子上的 stdout 不是终端，一判断颜色就全没了，而 Mac 这边其实能显示。所以改成用 `NO_COLOR` 手动关 |
| 时间用 `gettimeofday` + `localtime_r` | 精确到毫秒，方便看每一步花了多久。注意板子的时区可能是 UTC，和 Mac 差 8 小时 |
| 每条结尾都输出 `\033[0m` | 不恢复的话，后面所有输出（包括 shell 提示符）都会变成这个颜色 |

## 3. 在哪里能看到颜色

| 运行方式 | 有颜色吗 |
|---|---|
| CLion 底部的 Terminal 里运行 `./run_on_board_with_mac.sh` | ✅（2026-10-17 实测） |
| CLion 的 Shell Script 运行配置（Run 窗口） | 应该有（CLion 的 Run 窗口支持 ANSI 颜色，未实测） |
| macOS 自带的"终端"、iTerm2 | ✅ |
| 重定向到文件、用 `cat -v` 看 | ❌ 看到的是 `^[[32m` 这种原始字符 |
