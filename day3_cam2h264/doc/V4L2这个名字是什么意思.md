# V4L2 这个名字是什么意思

> 代码里到处是 `v4l2_xxx`、`V4L2_xxx`、`VIDIOC_xxx`，名字很怪。拆开看就好懂了。
> 相关：[guide/04 第 3 节](../guide/04_摄像头和V4L2知识.md)（V4L2 怎么用）、[videodev2.h是从哪来的](videodev2.h是从哪来的_内核uapi头文件.md)

---

## 1. V4L2 = Video for Linux 2

| 部分 | 意思 |
|---|---|
| **V** | Video，视频 |
| **4** | **for** 的谐音（four 和 for 读音一样；类似 `B2B` = business to business、`gr8` = great） |
| **L** | Linux |
| **2** | 第 2 版 |

连起来："Video for Linux, version 2"，**Linux 的视频设备接口，第二版**。也常写成 Video4Linux2。

## 2. 为什么有个 "2"

- **V4L（第一版）**：上世纪 90 年代末加进 Linux，最早给电视采集卡用，设计比较简单，后来不够用了
- **V4L2（第二版）**：1998 年开始重新设计，`videodev2.h` 开头写的作者 Bill Dirks 是主要设计者，2002 年前后进入内核
- 第一版大约 2011 年从内核里删掉了，现在只剩 V4L2，但名字里的 2 留了下来

> 年份凭记忆写的，没有核对原始资料，细节以 Linux 内核文档为准。

## 3. 代码里的名字怎么拆

| 名字 | 拆开 | 意思 |
|---|---|---|
| `linux/videodev2.h` | video dev(ice) 2 | 视频设备接口第 2 版的头文件 |
| `struct v4l2_buffer`、`v4l2_format`、`v4l2_capability` | v4l2 + 名词 | V4L2 定义的结构体 |
| `V4L2_PIX_FMT_NV12` | V4L2 + PIXel ForMaT + NV12 | V4L2 定义的像素格式常量 |
| `V4L2_BUF_TYPE_VIDEO_CAPTURE_MPLANE` | BUFfer TYPE + 视频采集 + Multi-PLANE | 缓冲区类型：多平面视频采集 |
| `V4L2_MEMORY_MMAP` | MEMORY + MMAP | 内存方式：驱动分配、mmap 过来用 |
| **`VIDIOC_QUERYCAP`** | **VID**eo + **IOC**tl + QUERY CAPability | ioctl 命令：查询能力 |
| `VIDIOC_S_FMT` / `G_FMT` / `TRY_FMT` | Set / Get / Try ForMaT | 设置 / 读取 / 试探格式 |
| `VIDIOC_REQBUFS` | REQuest BUFferS | 申请缓冲区 |
| `VIDIOC_QUERYBUF` | QUERY BUFfer | 查某块缓冲区的长度、偏移 |
| `VIDIOC_QBUF` / `VIDIOC_DQBUF` | Queue BUFfer / DeQueue BUFfer | 缓冲区入队（交给驱动）/ 出队（取回来） |
| `VIDIOC_EXPBUF` | EXPort BUFfer | 把缓冲区导出成 dma_buf fd |
| `VIDIOC_STREAMON` / `STREAMOFF` | STREAM ON / OFF | 开始 / 停止采集 |
| `v4l2-ctl` | v4l2 + control | 控制 V4L2 设备的命令行工具 |

记住一条：**`VIDIOC_` 开头的 = VID(eo) + IOC(tl)，都是传给 `ioctl()` 的命令。**

### 3.1 ⚠️ 最容易搞混：`V4L2_CAP_` 和 `V4L2_BUF_TYPE_`

名字几乎一样，但完全是两类东西（`videodev2.h` 里查的）：

| 常量 | 值 | 是什么 | 用在哪 |
|---|---|---|---|
| `V4L2_CAP_VIDEO_CAPTURE_MPLANE` | `0x00001000` | **能力标志位**（CAP = capability） | 和 `cap.capabilities` 做 `&`：`if (cap.capabilities & V4L2_CAP_VIDEO_CAPTURE_MPLANE)` |
| `V4L2_BUF_TYPE_VIDEO_CAPTURE_MPLANE` | `9` | **缓冲区类型**（一个枚举值） | 填进 `fmt.type`、`buf.type`、`req.type`、`exp.type` |

2026-10-18 写 M2 时真实踩过：判断能力时写成了 `cap.capabilities & V4L2_BUF_TYPE_VIDEO_CAPTURE_MPLANE`。video22 的 capabilities 是 `0x84201000`，和 9 做 `&` 结果是 **0**，程序就会以为"不支持多平面"然后退出。**编译器不会报错**（都是整数），只能靠记住：判断能力用 `CAP_`，填类型用 `BUF_TYPE_`。

## 4. V4L2 管的不只是摄像头

它是 Linux 里**所有"视频进出"设备的统一接口**：

| 设备 | 板子上 |
|---|---|
| 摄像头（经过 ISP） | video22、video31……（实测） |
| HDMI 输入 | video40 `stream_hdmirx`（2026-10-17 节点列表实测） |
| USB 摄像头、电视卡、收音机 | 插上就有 |
| 硬件编解码器 | 有些芯片用 V4L2 做编解码；Rockchip 用自己的 MPP，不走 V4L2 |

学会 V4L2，以后接 USB 摄像头、HDMI 采集，都是同一套：`open` → `ioctl` → `mmap` → `QBUF / DQBUF`。
