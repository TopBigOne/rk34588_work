# 程序里怎么找到摄像头节点（不写死 /dev/videoN）

> 自己写相机程序时，`open("/dev/video31")` 这种写死号码的写法，换个系统版本、换个摄像头接口就失效了。这一篇讲**程序怎么自己找出该打开哪个节点**。
> 本文的程序和输出都是 2026-10-17 在板子上实测的（IMX415 装在 MIPI CSI3）。
> 前置：[v4l2-ctl和media-ctl用法.md](v4l2-ctl和media-ctl用法.md)（entity、pad、link、`media-ctl -p`）、[guide/04](../guide/04_摄像头和V4L2知识.md) 第 2 节（mainpath、selfpath）

---

## 1. 先回答：video32 是怎么知道的

**问它本人。**每个 video 节点都知道自己叫什么，两种问法：

```bash
v4l2-ctl -d /dev/video32 --info | grep "Card type"    # Card type : rkisp_selfpath
cat /sys/class/video4linux/video32/name               # rkisp_selfpath
```

所以"主出口还是副出口"看**名字**就知道：`rkisp_mainpath` 是主出口，`rkisp_selfpath` 是副出口。

## 2. 光看名字为什么不够

板子上有两个 ISP，所以**同名的节点有两个**（实测）：

| 名字 | 节点 | 属于 | 能不能出图（摄像头装在 CSI3 时） |
|---|---|---|---|
| `rkisp_mainpath` | `/dev/video22` | ISP0 | ✅ |
| `rkisp_selfpath` | `/dev/video23` | ISP0 | ✅ |
| `rkisp_mainpath` | `/dev/video31` | ISP1 | ❌ `STREAMON` 报 `Operation not permitted` |
| `rkisp_selfpath` | `/dev/video32` | ISP1 | ❌ |

只有**接了摄像头的那个 ISP** 能出图。所以程序要回答两个问题：

1. **哪个 ISP 接了摄像头？**
2. **这个 ISP 的 mainpath 是几号？**

## 3. 思路：在程序里做 media-ctl 做的事

我们手动排查时是这样查的（[v4l2-ctl和media-ctl用法.md](v4l2-ctl和media-ctl用法.md) 第 3 节）：

1. `media-ctl -p` 找到哪张图里有摄像头 → `/dev/media1`
2. 看哪个 ISP 的输入连着这张图的 CIF → `/dev/media2`（ISP0）
3. `media-ctl -e rkisp_mainpath` 查它的节点 → `/dev/video22`

程序里把这三步改成调用 **Media Controller API**，也就是 `media-ctl` 底层用的那几个 ioctl（`<linux/media.h>`）：

| ioctl | 干什么 | 对应 media-ctl |
|---|---|---|
| `MEDIA_IOC_DEVICE_INFO` | 读这张图的基本信息（driver、model） | `-p` 开头那几行 |
| `MEDIA_IOC_ENUM_ENTITIES` | 一个一个列出图里的实体：名字、类型、设备号 | `-p` 里的 `- entity N: ...` |
| `MEDIA_IOC_ENUM_LINKS` | 列出某个实体"出去"的连线，以及有没有接通 | `-p` 里的 `-> "xxx":0 [ENABLED]` |

### 3.1 关键：两张图是怎么接起来的

摄像头和 ISP **不在同一张图里**（实测）：

| 图 | model | 里面有 |
|---|---|---|
| `/dev/media1` | `rkcif-mipi-lvds2` | 摄像头 `m00_b_imx415 3-001a`、CSI 接收 |
| `/dev/media2` | `rkisp0` | **一个名字叫 `rkcif-mipi-lvds2` 的实体** → ISP → mainpath |

ISP 那张图里有一个实体，**名字正好等于 CIF 那张图的 model**，它就是两张图之间的"桥"。它连到 ISP 的线是接通的（`[ENABLED]`），就说明这个 ISP 在处理这个摄像头的数据。

> 注意：两个 ISP 图的 model **都叫 `rkisp0`**（实测），所以不能靠 model 区分是哪个 ISP，要靠"桥"。

### 3.2 设备号怎么换成 `/dev/videoN`

`MEDIA_IOC_ENUM_ENTITIES` 返回的是**设备号**（主设备号:次设备号，比如 81:22），不是文件名。内核在 sysfs 里写着它们的对应关系（实测）：

```bash
cat /sys/dev/char/81:22/uevent
# MAJOR=81
# MINOR=22
# DEVNAME=video22        ← 前面加上 /dev/ 就是设备文件
```

## 4. 完整代码

一个独立的小程序，复制成 `find_camera.cpp` 就能编译（不依赖 MPP）。

```cpp
// find_camera：不写死 /dev/videoN，自动找出"接了摄像头的那个 ISP 的 mainpath"
//
// 思路（和 media-ctl 看到的接线图一样，只是改成在程序里用 ioctl 查）：
//   ① 打开每一个 /dev/mediaN，列出里面所有的实体（MEDIA_IOC_DEVICE_INFO + MEDIA_IOC_ENUM_ENTITIES）
//   ② 找到含有"摄像头"实体（类型 MEDIA_ENT_F_CAM_SENSOR）的那张图，记下这张图的 model（例如 rkcif-mipi-lvds2）
//   ③ 找到同时含有"同名实体"和 rkisp_mainpath 的那张 ISP 图，并确认这个实体到 ISP 的连线是接通的
//   ④ 把 rkisp_mainpath 的设备号（主设备号:次设备号）换成设备文件名：读 /sys/dev/char/主:次/uevent 里的 DEVNAME
#include <cstdio>
#include <cstring>
#include <string>
#include <vector>

#include <fcntl.h>
#include <linux/media.h> // Media Controller API：media-ctl 底层用的就是它
#include <sys/ioctl.h>
#include <unistd.h>

struct Entity {
    unsigned id;
    std::string name;
    unsigned type;
    unsigned major, minor; // 有设备文件的实体才有（video 节点、子设备）
    unsigned pads, links;
};

struct Graph {
    std::string path;  // /dev/mediaN
    std::string model; // MEDIA_IOC_DEVICE_INFO 里的 model
    std::vector<Entity> entities;

    const Entity* find(const std::string& name) const {
        for (const Entity& e : entities) {
            if (e.name == name) {
                return &e;
            }
        }
        return nullptr;
    }
};

// 设备号 → /dev/xxx：内核在 /sys/dev/char/主:次/uevent 里写着 DEVNAME=video22
static std::string devnode(unsigned major, unsigned minor) {
    char path[64];
    snprintf(path, sizeof(path), "/sys/dev/char/%u:%u/uevent", major, minor);
    FILE* fp = fopen(path, "r");
    if (!fp) {
        return "";
    }
    char line[128];
    std::string name;
    while (fgets(line, sizeof(line), fp)) {
        if (strncmp(line, "DEVNAME=", 8) == 0) {
            name = std::string("/dev/") + (line + 8);
            name.erase(name.find_last_not_of("\n") + 1);
        }
    }
    fclose(fp);
    return name;
}

// ① 读一张图：基本信息 + 所有实体
static bool load_graph(const std::string& path, Graph& g) {
    int fd = open(path.c_str(), O_RDONLY | O_CLOEXEC);
    if (fd < 0) {
        return false;
    }
    media_device_info info = {};
    if (ioctl(fd, MEDIA_IOC_DEVICE_INFO, &info) == 0) {
        g.path  = path;
        g.model = info.model;
    }
    // 遍历实体：id 填"上一个 id | NEXT 标志"，内核就返回下一个实体，直到返回失败
    unsigned lastId = 0;
    while (true) {
        media_entity_desc desc = {};
        desc.id = lastId | MEDIA_ENT_ID_FLAG_NEXT;
        if (ioctl(fd, MEDIA_IOC_ENUM_ENTITIES, &desc) != 0) {
            break;
        }
        g.entities.push_back({desc.id, desc.name, desc.type, desc.dev.major, desc.dev.minor, desc.pads, desc.links});
        lastId = desc.id;
    }
    close(fd);
    return !g.path.empty();
}

// ③ 在图 g 里，实体 from 有没有一条"接通的"连线连到实体 to
static bool has_enabled_link(const Graph& g, const Entity& from, const Entity& to) {
    int fd = open(g.path.c_str(), O_RDONLY | O_CLOEXEC);
    if (fd < 0) {
        return false;
    }
    std::vector<media_pad_desc> pads(from.pads);
    std::vector<media_link_desc> links(from.links);
    media_links_enum req = {};
    req.entity = from.id;
    req.pads   = pads.data();
    req.links  = links.data(); // 内核只返回从这个实体"出去"的连线
    bool found = false;
    if (ioctl(fd, MEDIA_IOC_ENUM_LINKS, &req) == 0) {
        for (const media_link_desc& l : links) {
            if (l.sink.entity == to.id && (l.flags & MEDIA_LNK_FL_ENABLED)) {
                found = true;
            }
        }
    }
    close(fd);
    return found;
}

int main() {
    // ① 读出所有的图
    std::vector<Graph> graphs;
    for (int n = 0; n < 64; n++) {
        Graph g;
        if (load_graph("/dev/media" + std::to_string(n), g)) {
            printf("%-12s model=%-18s %zu 个实体\n", g.path.c_str(), g.model.c_str(), g.entities.size());
            graphs.push_back(g);
        }
    }

    // ② 找摄像头：类型是 MEDIA_ENT_F_CAM_SENSOR 的实体
    int found = 0;
    for (const Graph& cifGraph : graphs) {
        for (const Entity& sensor : cifGraph.entities) {
            if (sensor.type != MEDIA_ENT_F_CAM_SENSOR) {
                continue;
            }
            printf("\n摄像头：\"%s\"  在 %s（model=%s）  子设备 %s\n", sensor.name.c_str(), cifGraph.path.c_str(),
                cifGraph.model.c_str(), devnode(sensor.major, sensor.minor).c_str());

            // ③ 找 ISP：这张 ISP 图里有一个和 CIF 图 model 同名的实体，而且它连到 ISP 的线是接通的
            for (const Graph& ispGraph : graphs) {
                const Entity* bridge = ispGraph.find(cifGraph.model);         // 例如 rkcif-mipi-lvds2
                const Entity* isp    = ispGraph.find("rkisp-isp-subdev");
                const Entity* mainp  = ispGraph.find("rkisp_mainpath");
                const Entity* selfp  = ispGraph.find("rkisp_selfpath");
                if (!bridge || !isp || !mainp || !has_enabled_link(ispGraph, *bridge, *isp)) {
                    continue;
                }
                // ④ 设备号 → 设备文件名
                printf("  → 接到了 %s（model=%s）\n", ispGraph.path.c_str(), ispGraph.model.c_str());
                printf("  → mainpath：%s   selfpath：%s\n", devnode(mainp->major, mainp->minor).c_str(),
                    selfp ? devnode(selfp->major, selfp->minor).c_str() : "-");
                found++;
            }
        }
    }
    if (!found) {
        printf("\n没有找到接了摄像头的 ISP（摄像头没装好？先看 dmesg | grep imx415）\n");
        return 1;
    }
    return 0;
}
```

### 4.1 运行结果（2026-10-17 实测）

```
/dev/media0  model=rkcif-mipi-lvds    13 个实体
/dev/media1  model=rkcif-mipi-lvds2   14 个实体
/dev/media2  model=rkisp0             11 个实体
/dev/media3  model=rkisp0             10 个实体

摄像头："m00_b_imx415 3-001a"  在 /dev/media1（model=rkcif-mipi-lvds2）  子设备 /dev/v4l-subdev2
  → 接到了 /dev/media2（model=rkisp0）
  → mainpath：/dev/video22   selfpath：/dev/video23
```

和手动用 `media-ctl` 查的结果完全一样，而且**代码里没有写任何号码**。换系统版本、换摄像头接口，它都能自己找对。

## 5. 在自己的相机程序里怎么用

第 4 节的查找逻辑已经整理成类 **`CameraFinder`**，在 `src/camera/camera_finder.h/.cpp`（2026-10-22 按 rk_work/代码规范.md 从 `FindCamera` / `find_camera.h` 改名；2026-10-17 用 day3 工程编译、`run_on_board_with_mac.sh` 上板运行，找到 `/dev/video22`）：

```cpp
#include "camera/camera_finder.h"

CameraFinder cameraFinder;
std::vector<CameraNode> cameras;
if (!cameraFinder.find(cameras)) {             // 第二个参数传 true 会打印查找过程
    printf("没找到摄像头\n");
    return -1;
}
int fd = open(cameras[0].mainPath.c_str(), O_RDWR | O_CLOEXEC);   // "/dev/video22"
```

`CameraNode` 里除了 `mainPath`，还有 `selfPath`（副出口）、`sensorSubdev`（摄像头子设备，调翻转用）、`cifMedia` / `ispMedia`（链路经过的两张图）。

同时保留命令行参数 `-d`：自动找的结果不对时（比如以后接了两个摄像头），可以手动指定。

**Rockchip 自己的 3A 服务就是这么做的**：它启动时也是遍历所有 `/dev/mediaN`、按名字找节点，它的日志里能看到 `get rkisp_mainpath devname: /dev/video22` 这样的行。

## 6. 三种做法对比

| 做法 | 例子 | 优点 | 缺点 |
|---|---|---|---|
| 写死号码 | `open("/dev/video22")` | 最简单 | 换系统、换接口就错 |
| 按名字找 | 遍历 `/sys/class/video4linux/*/name` 找 `rkisp_mainpath` | 简单，不怕号码变 | **有两个同名节点**，分不出哪个接了摄像头 |
| ⭐ 按链路找 | 本文的程序：从摄像头出发，顺着连线找到 ISP 的 mainpath | 换系统、换接口都能找对 | 代码多一点（100 多行） |

学习阶段写死 + `-d` 参数就够用；做成真正的产品时用第三种。
