## 1. 里程碑和验证方法

| # | 里程碑 | 怎么验证 | 状态 |
|:---:|---|---|:---:|
| **M1** | 编码器初始化：create → init → 设置参数 → SET_CFG | 运行后打印 `encoder ready: 1920x1080 stride 1920x1088`，没有报错 | ✅ |
| **M2** | 取 SPS/PPS 写入 `out.h264` | `xxd out.h264 \| head -3` 看开头：`00 00 00 01 67`（SPS）……`00 00 00 01 68`（PPS） | ✅ |
| **M3** | 申请 DRM 缓冲区 → **按 stride 逐行读 1 帧** → `sync_end` → 编码 1 帧 | 见第 4 节：ffprobe 看到 1 帧 `pict_type=I`；和原图对比 PSNR > 40 dB | ✅ |
| **M4** | 循环读完 60 帧，最后送 EOS，取完所有 packet | Mac 上用 VLC 能播放 2 秒的画面，**没有花屏、没有绿条**；ffprobe 看到 60 帧、1 个 I 帧 | ⬜ |
| **M5** | 加命令行参数：`-i -o -w -h -t h264\|h265 -rc cbr\|vbr\|avbr -bps -g` | `-t h265` 输出的 `out.h265` 也能播放 | ⬜ |
| **M6** | 统计：总帧数、总用时、平均 fps、实际码率、I 帧数量 | 程序结束时打印一行汇总，I 帧数和 ffprobe 一致 | ⬜ |

**M3 的关键代码思路（stride 拷贝）**：
```
uint8_t* dst = (uint8_t*)mpp_buffer_get_ptr(frm_buf);
// Y：1080 行，每行从文件读 1920 字节，写到 dst + row * hor_stride
// UV：540 行，每行从文件读 1920 字节，写到 dst + hor_stride * ver_stride + row * hor_stride
mpp_buffer_sync_end(frm_buf);      // 缓冲区是 CACHABLE 的，CPU 写完一定要刷缓存
```

## 3. M4 之后：整理成 `MppEncoder` 类

M4 能正常出片之后，再把 `main()` 里的"面条代码"拆进类里，用 RAII 管理资源，`goto CLEANUP` 就不需要了。

### 3.1 建议的文件结构
```
day1_yuv2h264/
├── CMakeLists.txt          ← add_executable 里加上 src/mpp_encoder.cpp
├── main.cpp                ← 参数解析、读文件、主循环、统计
├── src/
│   ├── mpp_encoder.h       ← MppEncoder 类的声明
│   └── mpp_encoder.cpp     ← MppEncoder 类的实现
└── demo_code -> ...        ← 软链接（只读参考）
```

### 3.2 `MppEncoder` 类的设计（C++17）
```cpp
struct EncoderConfig {
    int width = 1920, height = 1080;
    MppCodingType type = MPP_VIDEO_CodingAVC;    // H.265: MPP_VIDEO_CodingHEVC
    MppEncRcMode rc_mode = MPP_ENC_RC_MODE_CBR;
    int bps = 4'000'000;
    int fps = 30;
    int gop = 60;
};

class MppEncoder {
public:
    bool init(const EncoderConfig& cfg);                    // create → timeout → init → cfg → SET_CFG → header mode
    int  hor_stride() const;                                // 给外面按 stride 填数据用
    int  ver_stride() const;
    bool get_header(std::vector<uint8_t>& out);             // MPP_ENC_GET_HDR_SYNC
    bool encode(MppBuffer frame_buf, bool eos,
                std::vector<uint8_t>& out, bool& is_key);   // put_frame + get_packet
    ~MppEncoder();                                          // mpp_destroy、mpp_enc_cfg_deinit
private:
    MppCtx ctx_ = nullptr;
    MppApi* mpi_ = nullptr;
    MppEncCfg cfg_ = nullptr;
    int hor_stride_ = 0, ver_stride_ = 0;
};
```
> 输入缓冲区（MppBufferGroup + MppBuffer）可以放在 `main` 里管理，也可以再封装一个 `MppBufferPool` 类。Day 3 接摄像头时，输入来自摄像头的 DMA-BUF，所以**不要把"申请输入缓冲区"写死在编码器里面**。

整理完再跑一遍，输出文件应该和整理前**完全一样**（可以用 `md5` 对比）。

## 4. 怎么验证"编码 1 帧"（M3）

```bash
cd /Users/dev/Documents/AV/rk_test_data
adb pull /userdata/av/out.h264 out_m3.h264
FF=/usr/local/ffmpeg/4.4/bin
```

| 层 | 命令 | 预期（实测） |
|---|---|---|
| ① 程序本身 | `./run_on_board_with_mac.sh` | 没有 `[FAIL]`，打印 `frame 0 size 74674 bytes`，退出码 0；文件大小 = 40 + 74,674 = 74,714 |
| ② 码流参数 | `$FF/ffprobe -v error -show_entries stream=codec_name,profile,level,width,height -of default=nw=1 out_m3.h264` | h264 / High / 40 / 1920 / 1080 |
| ③ 帧数和类型 | `$FF/ffprobe -v error -show_frames -show_entries frame=pict_type,key_frame -of compact out_m3.h264` | 1 帧，`key_frame=1`，`pict_type=I` |
| ④ NAL 结构 | `xxd out_m3.h264 \| head` | SPS(67) → PPS(68) → SEI(06) → IDR(65) |
| ⑤ 画面（眼睛） | `$FF/ffmpeg -y -i out_m3.h264 -frames:v 1 out_m3.png && open out_m3.png` | 和原图第 0 帧一样，没有绿条、没有错位 |
| ⑥ 画面（数字） | 见下 | `PSNR y:47.65 u:60.63 v:61.41` |

```bash
$FF/ffmpeg -hide_banner -f rawvideo -pixel_format nv12 -video_size 1920x1080 -i in_1080p_60f.nv12 \
    -i out_m3.h264 -frames:v 1 -lavfi "[1:v][0:v]psnr" -f null - 2>&1 | grep PSNR
```
PSNR > 40 dB 说明肉眼看不出区别；< 20 dB 基本可以断定读错了（错位、颜色乱）。

**反向验证（可选）**：临时把 `read_nv12_frame` 里的 UV 起点改成 `dst + width * height`，重新跑，应该看到底部发绿、颜色错位，U/V 的 PSNR 明显下降。看完改回来。
