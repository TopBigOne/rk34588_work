# 03 · 重构成类：把 main() 拆开

> 分支：`day2_h2642yuv_most_light_refactor`
> 起点：`src/mpi_dec_most_light.cpp`（M1～M6 的面条代码，约 280 行，一个 `main()` + `goto CLEANUP`）
> 终点：和 Day 1 一样的目录结构，`main()` 只负责"组装"，资源全部 RAII 自动释放
>
> **验收标准始终不变**：每拆完一步，下面 3 条都要和重构前一模一样（见第 5 节）
> - `-n 60 -o /userdata/av/out.nv12` → md5 `5aea639a616d92bb8ef8af809eee5218`
> - 不带参数 → `frames : 1803`，走到 EOS 正常退出，exit 0
> - `-t vp8` → 打印用法，exit 255

---

## 1. 为什么要拆、拆完是什么样

现在的 `main()` 一个函数干了所有事：解析参数、建解码器、读文件、处理 info change、管内存池、写文件、统计、释放。问题：

| 问题 | 我们踩过的坑 |
|---|---|
| `goto CLEANUP` 要求所有变量挤在第一个 `goto` 前面 | `jump to label crosses initialization` 编译错误 |
| 释放要手写，成功 / 失败共用一个出口 | 成功时 `return 0` 跳过了释放；`exitCode` 初值写成 0，失败也返回 0 |
| 句柄传来传去，类型都是 `void*` | `decode_get_frame(decoderApi, ...)`、`deinit(&cfg)`，编译器都不报错 |
| 解码器的细节（info change、内存池）和流程混在一起 | 想看"主循环在干嘛"，得先跳过 30 行内存池代码 |

拆完以后：

```
                 ┌──────────────── DecodePipeline::run() ────────────────┐
                 │                                                       │
 StreamSource ──read──→ MppDecoder ──get_frame──→ FrameSink               │
 （ReadStream）  │     （info change、内存池          （WriteYuv）         │
                 │       都在里面处理掉）                                  │
                 │            └──────────add_xxx──────→ DecodeStats       │
                 └───────────────────────────────────────────────────────┘
```

和 Day 1 对照：

| Day 1（编码） | Day 2（解码） | 说明 |
|---|---|---|
| `app/args.*` | `app/args.*` | 命令行参数，现在的 `Args` / `parse_args` 直接搬过去 |
| `common/mpp_utils.h` | `common/mpp_utils.h` | **直接复制 Day 1 的**：`MPP_CHECK`、`FilePtr`、`MppBufferGroupPtr`、`MppFramePtr`、`MppPacketPtr` |
| `encoder/mpp_encoder.*` | `decoder/mpp_decoder.*` | 只管解码器本身：初始化、送码流、取图像、info change + 内存池、释放 |
| `source/frame_source.h` + `read_yuv.*` | `source/stream_source.h` + `read_stream.*` | 输入：一块一块提供码流（现在：读文件；以后：RTSP 拉流） |
| `sink/stream_sink.h` + `write_stream.*` | `sink/frame_sink.h` + `write_yuv.*` | 输出：接收解出来的图像（现在：写 NV12；以后：送显示、送 RGA、送编码器） |
| `pipeline/encode_stats.*` | `pipeline/decode_stats.*` | 统计：帧数、错误帧、info change、用时、fps、重试次数 |
| `pipeline/encode_pipeline.*` | `pipeline/decode_pipeline.*` | 流程骨架：送 → 取 → 写 → 统计，EOS 收尾 |
| `main.cpp` | `main.cpp` | 只负责组装 |

## 3. 每个类的接口

> 下面只给**头文件**（接口 + 注释），`.cpp` 里的实现你来写——实现基本就是把 `main()` 里对应的那段代码搬过去。

### 3.1 MppDecoder（最重要）

```cpp
// decoder/mpp_decoder.h
#pragma once
#include "common/mpp_utils.h"   // MppBufferGroupPtr、MppFramePtr
#include <cstdint>
#include <rockchip/rk_mpi.h>

// feed() 的结果
enum class FeedResult {
    Sent,    // 送进去了，可以读下一块
    Full,    // 输入队列满了：这块数据留着，等一会儿原样再送（正常的流量控制，不是错误）
    Error,   // 出错
};

// get_frame() 的结果
enum class GetResult {
    Frame,   // 拿到一个 MppFrame（可能是正常图像、错误帧、或者只带 EOS 的空帧，调用方再细分）
    None,    // 现在没有输出（非阻塞），回去继续送码流
    Error,
};

class MppDecoder {
public:
    MppDecoder() = default;
    ~MppDecoder();                                         // mpp_dec_cfg_deinit → mpp_destroy；内存池由成员 frameGroup_ 最后释放
    MppDecoder(const MppDecoder&)            = delete;     // 禁止拷贝：两个对象会 destroy 同一个 ctx
    MppDecoder& operator=(const MppDecoder&) = delete;

    /**
     * M1：mpp_create → mpp_init(MPP_CTX_DEC, type) → GET_CFG → split_parse = 1 → SET_CFG
     * @return 成功 true；失败打印出错的那一句，返回 false
     */
    bool init(MppCodingType type);

    /**
     * 送一块码流：mpp_packet_init → decode_put_packet → mpp_packet_deinit
     * MPP 收下 packet 时会把数据拷走（packet 不带 MppBuffer 的情况，mpp.cpp 第 433–440 行），
     * 所以每次都新建 packet、用完就 deinit；返回 Full 时调用方保留 data，下次原样再送
     * @param data  码流数据
     * @param size  字节数
     * @param eos   true = 这是最后一块，给 packet 打上 EOS
     */
    FeedResult feed(const uint8_t* data, size_t size, bool eos);

    /**
     * 取一个输出帧：decode_get_frame
     * info change 在这里面处理掉（建池子 / clear → limit_config → SET_EXT_BUF_GROUP → SET_INFO_CHANGE_READY），
     * 处理完接着取，调用方永远拿不到 info change 帧
     * @param frame  输出参数：拿到的帧（RAII，离开作用域自动 mpp_frame_deinit）
     */
    GetResult get_frame(MppFramePtr& frame);

    RK_S32 info_change_count() const { return infoChangeCount_; }

private:
    /**
     * 处理 info change：打印宽高 stride buf_size，配置内存池，通知解码器继续
     * @return 成功 true
     */
    bool handle_info_change(MppFrame frame);

    // ⚠️ 成员析构顺序 = 声明的相反顺序。frameGroup_ 必须在 ctx 销毁之后才释放：
    //    ctx 和 cfg 在析构函数体里手动释放（函数体先执行），frameGroup_ 是成员，函数体执行完才析构 → 顺序正确
    MppBufferGroupPtr frameGroup_;            // 解码输出用的内存池（第一次 info change 时创建）
    MppCtx decoderCtx_    = nullptr;
    MppApi* decoderApi_   = nullptr;
    MppDecCfg decoderCfg_ = nullptr;
    RK_S32 infoChangeCount_ = 0;
};
```

设计要点：

- **info change 是解码器内部的事**：它只和内存池有关，pipeline 不需要知道。所以 `get_frame` 里遇到 info change 就自己处理完、接着再取一次，外面拿到的只有"图像 / 错误帧 / EOS 空帧"。
- **`feed` 每次新建 packet**：现在的面条代码是"packet 留着，队列满时重送同一个 packet"。拆开后改成"数据留着，每次重新包一个 packet"，因为 MPP 送进去时会拷数据，packet 本身很便宜。这样 `MppDecoder` 不用存"上一次没送进去的 packet"这个状态。
- **内存池放在类里**：它的生命周期和解码器绑在一起（ctx 销毁后才能释放），放在类里最自然。用 Day 1 的 `MppBufferGroupPtr` 管理，不用手写 `mpp_buffer_group_put`。

### 3.2 StreamSource / ReadStream

```cpp
// source/stream_source.h
#pragma once
#include <cstdint>
#include <vector>

class StreamSource {
public:
    virtual ~StreamSource() = default;
    /**
     * 读下一块码流
     * @param data    输出参数：这一块的数据（读到多少就是多大）
     * @param isLast  输出参数：true = 这是最后一块（文件读完了）
     * @return 成功 true；读出错返回 false
     */
    virtual bool read(std::vector<uint8_t>& data, bool& isLast) = 0;
};

// source/read_stream.h
class ReadStream : public StreamSource {
public:
    bool open(const char* path, size_t chunkSize = 64 * 1024);
    bool read(std::vector<uint8_t>& data, bool& isLast) override;   // fread 一块；读不满 = 最后一块
private:
    FilePtr file_;          // RAII：析构时 fclose
    size_t chunkSize_ = 0;
};
```

### 3.3 FrameSink / WriteYuv

```cpp
// sink/frame_sink.h
#pragma once
#include <rockchip/rk_mpi.h>

class FrameSink {
public:
    virtual ~FrameSink() = default;
    /**
     * 输出一帧图像
     * @param frame  正常的图像帧（有 buffer，没有 errinfo / discard）
     */
    virtual bool write(MppFrame frame) = 0;
};

// sink/write_yuv.h
class WriteYuv : public FrameSink {
public:
    bool open(const char* path);                // fopen "wb"
    bool write(MppFrame frame) override;        // 就是现在的 write_nv12_frame
private:
    FilePtr file_;
};
```

不带 `-o` 时不写文件：pipeline 拿到的 `FrameSink*` 是 `nullptr`，就不调用 `write`。

### 3.4 DecodeStats

// pipeline/decode_stats.h
class DecodeStats {
public:
    void start();                       // 开始计时
    void stop();                        // 停止计时
    void add_frame()     { decodedFrameCount_++; }
    void add_error()     { errorFrameCount_++; }

    RK_S32 frame_count() const { return decodedFrameCount_; }
    void print_summary(const char* input, const char* output, RK_S32 infoChangeCount) const;   // 现在 main 末尾那段 summary
private:
    RK_S32 decodedFrameCount_ = 0;
    RK_S32 errorFrameCount_   = 0;
    long putRetryCount_       = 0;
    double seconds_           = 0;
    std::chrono::steady_clock::time_point startTime_;

### 3.5 DecodePipeline

```cpp
// pipeline/decode_pipeline.h
class DecodePipeline {
public:
    /**
     * @param sink  可以是 nullptr：不写文件
     */
    DecodePipeline(StreamSource& source, MppDecoder& decoder, FrameSink* sink, DecodeStats& stats);

    /**
     * 主循环：读一块 → feed（Full 就等 1ms 重送）→ 把能取的帧全取出来 → 写 / 统计
     * 结束条件：拿到 EOS 帧，或者解够 maxFrames 帧（0 = 不限）
     */
    bool run(int maxFrames);

private:
    /**
     * 把解码器现在能给的帧全取出来（内层循环）
     * @return 成功 true；outputEos / reachedLimit 通过成员变量带出来
     */
    bool drain_frames(int maxFrames);

    StreamSource& source_;
    MppDecoder& decoder_;
    FrameSink* sink_;
    DecodeStats& stats_;
    bool outputEos_    = false;
    bool reachedLimit_ = false;
};
```

### 3.6 main.cpp（拆完以后大概这样）

```cpp
int main(int argc, char** argv) {
    Args a;
    if (!parse_args(argc, argv, a)) { usage(argv[0]); return -1; }

    // 声明顺序 = 析构顺序的反过来：pipeline 只存引用，要声明在最后
    ReadStream reader;
    WriteYuv writer;
    MppDecoder decoder;
    DecodeStats stats;

    if (!decoder.init(a.type)) return -1;
    if (!reader.open(a.streamInputPath)) return -1;
    if (a.yuvOutputPath && !writer.open(a.yuvOutputPath)) return -1;

    DecodePipeline pipeline(reader, decoder, a.yuvOutputPath ? &writer : nullptr, stats);
    if (!pipeline.run(a.maxFrames)) return -1;

    stats.print_summary(a.streamInputPath, a.yuvOutputPath, decoder.info_change_count());
    return 0;                // 什么都不用释放：析构函数自动处理
}
```

## 4. 分 6 步拆（每步都能编译、能上板验收）

**一次只拆一块，拆完就跑第 5 节的 3 条验收**。md5 不对就说明这一步拆坏了，范围很小，好查。

| 步骤 | 做什么 | 改完 main 里还剩什么 |
|---|---|---|
| **R1** | 建目录；`mpi_dec_most_light.cpp` 改名 `src/main.cpp`；复制 Day 1 的 `common/mpp_utils.h`；CMakeLists 加 `target_include_directories(... src)` | 代码一行不改，只是挪位置 |
| **R2** | `Args` / `parse_args` / usage 搬到 `app/args.*` | 少了 40 行参数解析 |
| **R3** | 写 `MppDecoder`，main 里的 create / init / cfg、`put_packet`、`get_frame` + info change + 内存池 全部换成调用它 | **最大的一步**。`decoderCtx / decoderApi / decoderCfg / frameGroup` 这 4 个变量从 main 里消失 |
| **R4** | 写 `StreamSource` + `ReadStream`、`FrameSink` + `WriteYuv` | `fopen / fread / fclose` 和 `write_nv12_frame` 从 main 里消失 |
| **R5** | 写 `DecodeStats` | 计数变量和 summary 从 main 里消失 |
| **R6** | 写 `DecodePipeline`，主循环搬进去；main 变成第 3.6 节那样 | `goto CLEANUP` 和 `CHECK` 宏彻底消失 |

每一步提交一次（代码单独提交），提交信息写 `R1` ～ `R6`。

## 6. 容易踩的坑

| 坑 | 后果 | 怎么避免 |
|---|---|---|
| `~MppDecoder` 里先释放内存池、后 `mpp_destroy` | 解码器销毁时参考帧还在用池子里的 buffer | 池子用成员 `MppBufferGroupPtr`，ctx / cfg 在析构函数体里释放（函数体先跑，成员后析构） |
| info change 帧忘了 deinit | 内存泄漏 | `get_frame` 里用 `MppFramePtr` 接，处理完自动释放 |
| `get_frame` 把 info change 帧交给了外面 | pipeline 把它当图像写文件（没有 buffer） | 处理完 info change 后**再取一次**，直到拿到非 info change 帧或者 `None` |
| `feed` 返回 Full 时调用方去读下一块 | 丢数据，画面花 | Full 时**不读新数据**，等 1ms 后原样再 feed |
| `MppFramePtr` 交给 sink 之前就被 reset | sink 拿到野指针 | sink 只借用 `frame.get()`，所有权留在 pipeline 的局部变量里，写完它才析构 |
| `DecodePipeline` 声明在 decoder / reader 前面 | pipeline 析构时引用的对象已经没了 | main 里**最后**声明 pipeline（和 Day 1 一样） |
| 复制 Day 1 的 `mpp_utils.h` 里多了用不到的宏（`ALIGN`） | 没影响 | 留着就行，或者删掉 |
| 不再有 `CHECK` + `goto`，改用 `MPP_CHECK(expr, false)` 直接 return | 没影响，RAII 会释放 | Day 1 的 `MPP_CHECK` 第二个参数是失败时的返回值 |
