## 本周目标

1. **（可选，加深）** 不用 FFmpeg 的 rtmp 输出，自己写最小推流端：握手 → connect → createStream → publish → 发 FLV tag。
2. **（必做）** 同一路画面，分别用 RTSP（N1）和 RTMP 输出，用同一种方法测端到端延迟，对比断线恢复。
3. N11 收尾：故障注入、模拟面试、问题案例库。

## 学完能回答的问题

1. RTMP 的 chunk 为什么要分块？chunk stream id 和 message stream id 有什么区别？
2. 你测出来的 RTSP 和 RTMP 延迟各是多少？差在哪个环节？
3. 推流端断网 10 秒再恢复，RTMP 推流会怎样？要做什么处理？
4. "端到端延迟"你是怎么测的？误差有多大？

## 开始前要准备好

- **面试多的那周主线可以停**，被问倒的问题记下来，回来补。手写推流是可选的，面试多的话直接跳过任务 1～3。
- 代码分工：按 C 方案（**待确认**），延迟对比的工具由 Claude 写；任务 1～3 手写推流如果做，由你写。
- 延迟测法（本周和第 32 周都用这个）：Mac 屏幕上开一个毫秒计时器，摄像头对着它拍；播放窗口和计时器放在同一个屏幕上，截图，两个时间相减就是端到端延迟。播放器要关掉缓冲（ffplay 用 `-fflags nobuffer`；VLC 默认有网络缓存，要调小），否则测的是播放器的缓存。
